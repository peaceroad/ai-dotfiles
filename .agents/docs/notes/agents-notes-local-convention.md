# `~/.agents/notes/`を保守記録の入口として使う考え方

> **位置付け：** これは、プロジェクトやセッションをまたいで再検討する保守記録のためのローカル規約です。Agent Skillsの標準ではなく、スキルやワークフローを使うための必須要件でもありません。

この文書では、`~/.agents/notes/`に共通する考え方を説明します。`agent-workflow-design`がこの場所を候補にする条件と同梱テンプレートとの関係は、[skill-creator、prompt-design、agent-workflow-designの役割と使い分け](skill-creator-prompt-design-agent-workflow-design.md#改善記録とruntime-stateを必要な場合だけ持つ)で説明しています。採用済みの運用規約は、[`~/.agents/notes/README.md`](../../notes/README.md)を正本とします。

改善の気付きが得られても、その場でスキル、プロンプト、設定へ反映するとは限りません。追加の事例と比較したい候補や、将来の保守に必要な判断理由だけを残したい場合があります。既存のプロジェクト、プラグイン、ランタイム、コントローラー、外部システムに適切な保存先がないときは、`~/.agents/notes/`を利用者単位の入口として検討できます。

この場所は、作業中の情報を何でも蓄積するためのノート置き場ではありません。保存する目的、所有者、読み直す条件、削除条件を先に決め、後の判断を変え得る最小限の記録だけを扱います。

## この方法が候補になる場面

`~/.agents/notes/`は、次の条件が重なるときに候補になります。

- 1つの実行結果だけでは採否を決めず、別のプロジェクトやセッションの事例と比較したい。
- 未解決の候補を、採用済みのスキル、設定、ポリシーから分離したい。
- 判断後も、採用理由、見送った選択肢、重要な影響、再検討条件の一部を残す必要がある。
- 記録の所有者が、書き込み、競合、再読、整理の方法を管理できる。

プロジェクトやランタイムなどに正本となる保存先がある場合は、そちらを使います。公開用の解説や利用ガイドは、所有するプロジェクトやパッケージの`docs/notes/`などへ置きます。公開文書は読者向けの説明であり、候補のライフサイクルを管理する記録ではありません。

## 最小の配置案

具体的な記録と書き込み範囲が決まった後、所有者を先に置く構成にします。

```text
~/.agents/notes/
└── <owner-id>/
    ├── candidates/
    │   └── <candidate-set-id>/
    └── decisions/
```

記録ファイルとその内容は利用者が所有します。`<owner-id>`は、記録の形式、書き込み、競合処理、再読、整理を定める保守契約の所有者を表します。プラグインがライフサイクルを管理するならプラグインID、単独のスキルが管理するならスキル名、その他の場合は安定したコントローラーやアプリケーションの識別子などが候補になります。保守方法を設計しただけのスキルや、一時的に処理を呼び出したスキルを所有者にはしません。

この案を説明しただけでは、`~/.agents/notes/`、所有者ディレクトリ、候補、判断記録を作成しません。規約を採用するときは、`~/.agents/notes/README.md`を運用上の正本として設置または調整します。既存のファイルがある場合は、内容を確認し、適用できる規則を残したうえで調整します。採用後も、具体的な記録と書き込み範囲が決まるまでは、所有者ディレクトリや記録を増やしません。

## 候補と判断記録を分ける

`candidates/`には、後から得られる証拠と比較する価値がある未解決の判断を置きます。候補の存在は、規則が採用されたことや、正しさが確認されたことを意味しません。採否を判断するときは、候補が参照するセッション、成果物、検証結果、利用者の修正などを改めて確認します。

`decisions/`には、判断後も将来の保守へ影響する理由だけを選んで置きます。採用理由、採用しなかった有力な代替案、重要なトレードオフ、再検討条件などが、正本だけではわからない場合に使います。完了した候補をすべて履歴として移す場所ではありません。

採用済みの動作は、適用されるスキル、コード、設定、ポリシー、評価定義などの正本へ反映します。ノートは保守判断を支えますが、存在するだけで動作を有効にしたり、正本を置き換えたりしません。

## 置かない情報

次の情報は`~/.agents/notes/`へ置きません。

- 生のセッションログや会話履歴
- 成果物のコピーや一時的な作業ファイル
- 生成された評価結果、スコア、トレース
- チェックポイント、進捗、ロック、再試行回数
- キャッシュや、再開に必要なランタイム状態
- 採用済みの利用者設定

ランタイム状態は、ランタイム、コントローラー、プラグイン、外部システム、またはプロジェクトの状態契約が定める場所へ置きます。状態契約で管理される保存先がなければ、ノートを代用せず、状態契約を先に定めます。採用済みの利用者設定を外部へ分離する場合は、[`~/.agents/config/`を利用者所有の設定面として使う考え方](agents-config-local-convention.md)を参照してください。

## 読み直す条件を限定する

通常のタスクで`~/.agents/notes/`全体を走査しません。利用者が対象を指定した場合、または所有者の保守ワークフローが定めた再読条件に達した場合だけ、対象となる所有者の記録を読みます。他の所有者や、関係のない判断記録まで広げません。

既存の保存先へ新しい候補を書こうとする時点は、同じ所有者の関係する候補を確認する契機になります。同じ候補や実質的に同じ候補があれば、重複して追加せず、今回の証拠を使って再評価します。

## 候補を残し続けない

候補は、次のいずれかに該当したら、所有者の整理方針に従って削除します。

- スキル、コード、設定、ポリシー、評価定義などへ正式に反映した。
- 既存の規則ですでに扱えていると確認した。
- 採用しないと判断した。
- 根拠を確認できなくなった。
- 対象範囲や保守の必要性がなくなった。

判断記録は、将来の保守に影響する間だけ正本との対応を保ちます。判断が大きく変わった場合は、生の実行履歴を追記し続けず、所有者の規約に従って改訂または置き換えます。

## `config`やランタイム状態との違い

| 種類 | 役割 | 動作への反映 |
| --- | --- | --- |
| 利用者設定 | 採用済みの好みやデフォルト | 対応する読み込み契約がある場合に適用する |
| 未解決候補 | 後から得られる証拠と比較する判断材料 | 自動では適用しない |
| 判断記録 | 将来の保守に必要な理由や再検討条件 | 自動では適用しない |
| ランタイム状態 | 次の処理、再開、排他制御に必要な情報 | ランタイムやコントローラーの状態契約に従う |
| 公開ノート | 考え方や使い方を読者へ説明する文書 | 設定や保守記録としては扱わない |

区分の基準はファイル形式ではなく、情報が次の動作を直接決めるのか、将来の保守判断を支えるのか、実行を再開するために必要なのか、読者へ説明するためのものかという役割です。

## 採用するときに決めること

この方法を採用する場合は、少なくとも次を所有者の規約で定めます。

- `owner-id`と、扱う候補・判断の範囲
- 記録ごとに必要な最小限の内容
- 書き込みを許可する条件と担当
- 複数の書き手がいる場合の競合処理
- 読み直し、再検討、採否判断の契機
- 正本へ反映する方法と、候補の削除条件
- 判断記録を残す条件と、改訂・置換の方法

項目を埋めること自体を目的にせず、後の判断を再開するために必要な情報だけを求めます。新しい保存先を設けたり、利用者単位の場所へ書き込んだりする場合は、場所、目的、所有者、読み直す条件、整理方法を示してから作成します。
