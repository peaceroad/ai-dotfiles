# 納品状況の取得・整理と入荷待ちの設計

単一の実行主体が A 社・B 社の取得ジョブを並行して開始し、返った会社から納品物を整理する。比較表の確定だけを両社の結果に依存させる。進められる作業がなくなったら既存のイベント継続機構に制御を返し、入荷待ちは静かに継続する。追加エージェント、新しい状態保存先、独自の予算・タイムアウトは設けない。

成果物は、依頼時点の「今日」を対象日として、会社別の必要納品物一覧と両社の比較表とする。元の結果にある納期・入荷状況・数量などを根拠に、入荷済み、未入荷、確認が必要な項目を整理する。情報が欠けている箇所は未確認として残し、推測で入荷済みにしない。比較表には対象日と取得時点を示す。

| 状況・契機 | 次の処理 |
| --- | --- |
| 初回開始 | `run_lookup(A)` と `run_lookup(B)` を独立して非同期開始し、それぞれのジョブ ID を既存ランタイムに引き継ぐ。片方の終了を待ってから他方を開始しない。 |
| 未処理の新しい結果がある | 対応する会社・ジョブ・対象日を照合し、その会社の必要納品物一覧を作成・更新する。他社が継続中でもこの処理を進める。 |
| 両社の有効な結果が揃った | 整理済みの会社別一覧を合わせて比較表を確定する。片方が未取得・失敗の間は比較表を未完了として扱う。 |
| 独立して進められる作業がなく、取得が継続中 | `wait_jobs` で未完了ジョブの新しい結果を受け取る。結果を受け取るたびに処理可能な会社へ進み、両社の終了を一括して待つことを会社別整理の前提にしない。 |
| 継続中または変化のない通知だけが返る | 未完了のジョブ ID と現在の目的を保持する既存のイベント継続機構に引き継ぎ、その実行を終了して待機する。即時の再呼び出し、同じ状態の再分析、定例の状況報告を繰り返さない。 |
| 取得結果は揃ったが、必要な納品物が未入荷 | 現時点の比較表を保持し、未入荷の対象について入荷を待つ。取得ジョブの完了を、納品物の入荷や依頼全体の完了と同一視しない。 |
| イベントで再開 | まず現在の目的、既存ジョブの状態、整理済み成果物、未入荷項目を照合する。ジョブの新しい結果を受け取り、入荷イベントなら対象会社の最新状況を再取得して必要な箇所を更新する。更新がなければ通知せず待機へ戻る。 |
| 取得失敗 | 成功した他社の整理は進める。失敗した取得はツールの再試行契約とランタイム設定に従って扱い、既存ジョブの状態が不明なまま重複起動しない。再開不能な失敗は、未完了範囲と必要な対応をユーザーに知らせる。 |

制御の所有者は、取得・待機の結果契約がツール、ジョブ管理・イベント継続・制限の適用がランタイム、納品物の解釈と必要な通知の判断がモデルとする。会社別の整理結果と比較表を再開時に参照できる形で既存の成果物保持機構に残し、処理済みの結果と新しい結果を区別する。通知の重複も既存ランタイムの継続状態で防ぐ。ランタイムに既にあるジョブ ID・目的の保存を別の台帳に複製しない。

イベント継続が可能なことは依頼の前提として使う。一方、入荷そのものを知らせるイベントの供給元と、イベント後にどの会社を再取得できるかはツール契約だけでは確定しないため、実装時の接続条件とする。既存の入荷通知または納品状況更新イベントを継続機構へ接続し、接続できない場合は、その不足を明示して入荷監視が動作すると約束しない。

「必要なときだけ知らせて」という既存の依頼をそのまま引き継ぐ。入荷によって必要物が揃ったとき、今日の対応判断が変わったとき、確認や対処が必要な失敗が起きたときに、変化と必要な行動を短く通知する。ジョブ開始、単なる継続中、変化のない再開は通知しない。待機継続の再承認は求めない。

必要納品物の整理と両社比較が完了し、待つ必要のある対象がなくなったら完了を通知して監視を解除する。予算・タイムアウトはランタイム設定に従い、到達時は未完了部分と保持されたジョブを引き継ぐか停止する。独自の回数や時間で停滞と判定せず、未完了を成功として扱わない。キャンセル時も監視を解除し、実行中ジョブの停止可否は実際のツール契約に従う。

実装確認では、A 社だけが先に返る場合に A 社の整理が先行すること、通知が変わらない場合に継続機構へ戻って静かに待つこと、片社失敗でも他社の整理が残ること、再開後の重複通知を防いで入荷分だけ更新できることを確認する。両社の結果がない比較表を確定しないことと、最終入荷後に監視が終了することも確認する。この成果物は設計のみで、実サービス操作・対象ワークフロー実行による検証は行っていない。
