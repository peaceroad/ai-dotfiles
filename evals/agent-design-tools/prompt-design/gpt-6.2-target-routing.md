# GPT-6.2移行時の参照選択

用途は、モデルが未指定、複数指定、制御設計だけ、ワーカー指示の追加という4条件の回帰確認。以下は新規コンテキストの1担当に合成依頼4件をまとめて与えた試行である。依頼はスキルを明示した。参照選択は担当の申告、引用は最終応答の抜粋、判定は主担当が行った。自動選択、個々のモデルでの下流実行、旧版との優劣は評価していない。

## ケースと判定

1. **対象未指定。** 「Codexで障害レポートを要約する指示を作って。断定の強さと未確認事項は保持。」期待は6.2 Astraを設計対象とし、確度を保つ指示を返すこと。担当はprompt-design本文と6.2参照を選び、「原因や復旧状況が推定・調査中なら、その状態を明記してください」と回答した。条件を満たす。
2. **世代横断。** 「同じ指示を6.2 SolとGPT-6 Astraに共通配布したい。移行はしない。どこを調整する？」期待は両方の対象を保持すること。担当は1の資料と旧6 Astra参照を選び、「上の指示はそのまま共通配布できます」と回答し、両モデルで影響範囲と確度を比較する入力を示した。条件を満たす。
3. **制御のみ。** 「ビルド終了を監視して再開時に二重公開を防ぐ制御設計だけ欲しい。ランタイムはビルドIDの照会と公開先のバージョン照会に対応。」期待はモデルを選ばず、照会と重複防止の保証を区別すること。担当はworkflow本文、制御、状態・復旧の参照を選び、「公開応答が失われた後は再照会し、結果が判別できなければ保留します」と回答した。並行再開に必要な条件も示しており、条件を満たす。
4. **ワーカー指示の追加。** 「その設計に既存の6.2 Solワーカー向けレビュー指示を追加。実際の公開はしない。」期待は制御設計を維持し、指示だけをSolに合わせること。担当は3の資料にprompt-design本文と6.2参照を追加し、「仕様から判断できない点は未確認として示し、レビュー結果を返してください」と指示を書いた。公開権限を渡さない設計であり、条件を満たす。

### 版の競合に関する追試

Bから残った疑問を調べるため、週次の同一版を二人が審査し、差し替え中に結果がそろった場合について「版番号付きの履歴」と「現在有効な審査結果」の採用条件を別々に尋ねた。使えるのは版付き結果の保存だけとした。上の改訂版と、状態・復旧参照に次の文を加えた比較案を別々の新規担当に渡した。

> A report for a named snapshot can remain valid after the source changes. If a report must still be current when committed, serialize the commit with source updates or make the commit conditional on the expected version. A separate read immediately before the commit leaves a race.

両者とも、旧版の履歴を採用できること、現行欄の確定には条件付き更新または直列化が要ること、確定後の差し替えでは現行欄を審査待ちに戻すことを説明した。追加文の採用は見送った。これは設計回答の比較で、実システムの競合試験ではない。
