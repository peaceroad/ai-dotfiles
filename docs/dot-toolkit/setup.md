# dot-toolkitのインストール・初期設定・変更

まずChatGPT Webで`dot-toolkit`をインストールし、メインのdotから利用できることを確認します。その後、必要に応じて個別指示やタスク用スキルをdotのクラウドへ用意します。このページでは、利用者が行う操作と、dotに依頼して選ぶことを順に説明します。

すでに0.1を使っている場合も、新しいプラグインが利用できるかを確認してから[移行の節](#01から02へ移行する)へ進みます。既存ファイルを新規設定として上書きしないでください。

## 1. ChatGPT Webでプラグインをインストールする

### パッケージを用意する

配布者からdot-toolkitのZIPまたは共有プラグインを受け取ります。ソースから作る場合は、このリポジトリで使う0.2のコミットを選び、[plugins/dot-toolkit/](../../plugins/dot-toolkit/)にある`plugin.json`、`README.md`、`skills/`を、そのままZIPの直下に入れます。リポジトリ全体や、外側の`dot-toolkit/`フォルダーを包んだZIPにはしません。生成ZIPは公開ソースへコミットせず、個別指示や実際の管理記録を混ぜないでください。

Gitで取得したソースから作る場合は、使う0.2のコミットへ切り替えたうえで、リポジトリのルートから次を実行できます。出力先に同名ZIPがあれば、先に出力名を変えてください。

```sh
git archive --format=zip --output=../dot-toolkit-0.2.0.zip HEAD:plugins/dot-toolkit
```

親ディレクトリに、プラグインのファイルだけを含むZIPを作成します。`HEAD`に含まれるコミット済みの内容が対象で、未コミットの編集は入りません。

### Webで追加・インストールする

ブラウザーでChatGPTを開き、dotを使うアカウントとワークスペースを選びます。配布されたZIPを使う場合と、すでに共有されているプラグインを使う場合では、最初の操作が異なります。

- **ZIPを受け取った場合**：利用できるプラグインアップロード機能からZIPを追加します。アップロード権限のあるワークスペース管理者向けの経路は、管理コンソールで対象ワークスペースのPluginsを開き、Add → Upload pluginです。表示される機能や必要な権限はアカウント・ワークスペースによって異なります。
- **プラグインが共有されている場合**：ChatGPTのPluginsから、その`dot-toolkit`を開きます。

追加したプラグインの詳細を開き、Install pluginが表示される場合は選択して、インストール済みで利用可能になっていることを確認します。ZIPのアップロードと、利用者のアカウントでのインストールは分けて確かめます。操作の提供条件はOpenAIの[プラグイン案内](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt)を参照してください。アップロードやインストールの項目がなければ、提供条件と権限を確認します。

チャットへのZIP添付、ライブラリへの保存、dotのクラウドへの展開だけでは、プラグインのインストール確認になりません。このガイドはdot-toolkitを使い始める経路としてChatGPT Webを案内しており、すべてのプラグインがWebでしかインストールできないとするものではありません。

### メインのdotから確認する

インストール後は、メインのdotへ「インストールしたdot-toolkitのdot-guidelinesを読めるか確認して」と依頼します。確認するのは、実際に利用できる共通スキルと、その時点の作業に必要な同梱リファレンスです。版の情報が得られる場合は、意図した0.2.0かも確認します。

ローカルのCodexに同名プラグインがある、リポジトリの`SKILL.md`を読める、といった状態だけでは代用できません。dotから見えない場合は、使用中のアカウント・ワークスペース、プラグインの状態、確認できた版を調べます。不明な状態で再インストールを繰り返したり、端末間で反映されると決めつけたりしません。

## 2. 必要なクラウド設定を依頼する

個別指示をファイルで管理したい場合や、タスク用スキルをdot自身のクラウドへ置きたい場合は、メインのdotに「dot-toolkitで初期設定して」と依頼します。共通指示だけを使うために、個別ファイルやタスク用スキルを必ず作る必要はありません。

dotは同梱の[初期設定手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/setup.md)を使い、既存のファイルと編集を確認してから進めます。0.2では別の`dot-setup.md`を添付しません。手順の説明を求めただけでは設定を書き換えません。

### 個別入力を選ぶ

未提供で状態が分からない場合は、次の2つをそれぞれ選びます。

- **個別指示**：今渡す・後で渡す・今回は不要。利用者固有の条件や、特定の仕事で読む資料を指定します。
- **追加スキル候補**：今渡す・後で渡す・今回は不要。次の共通候補以外に検討したいスキルを指定します。

一方を不要としても、もう一方まで不要にはなりません。後回しや提供待ちの内容があれば、再開に必要な判断だけを非公開で残します。状態を表すだけの空ファイルは不要です。入力が保留でも、その内容に具体的に依存しない作業は進められます。

### 使うスキルを選ぶ

共通候補は次の4スキルです。まず用途、取得元、提案する版、必要な環境、現在の配置状態を確認します。

| スキル | 主な用途 |
| --- | --- |
| `agent-workflow-design` | 継続・反復する仕事の役割分担、待機、再開、終了の設計 |
| `prompt-design` | モデルへ渡す指示の設計・レビュー・改訂 |
| `agent-improve` | スキルやプラグインの比較評価と改善実験 |
| `plugin-creator-agent-plugins` | プラグインの作成・検証・移行・パッケージ化 |

共通候補と個別の追加候補は、別々に追加・更新の対象を決めて承認します。この区分は候補の出所を示し、取得元リポジトリの公開・非公開とは関係ありません。どちらも見送れます。候補への掲載や「追加なし」の回答だけで、既存スキルを更新・削除しません。

承認したスキルは、`SKILL.md`と必要な参照・スクリプト・素材をまとめて、dotのクラウドへ配置します。これは最初に行ったdot-toolkit自体のインストールとは別の作業です。アプリ側の既存スキルを自動でコピーしたり、未選択の依存スキルやランタイムを追加したりもしません。保存場所と管理記録は[ファイル構成](instructions.md#クラウドの基本配置)にあります。

## 完了を確認する観点

通常利用を始める前に、次の3点を確認します。

1. **プラグイン**：メインのdotから意図した共通スキルと、今回の作業に必要な同梱資料を読めたか。
2. **個別入力**：適用済み、提供待ち、後回し、不要のどの状態か。機密内容を報告へ転載する必要はありません。
3. **スキル配置**：承認したスキルが揃い、ファイル内容、採用記録、選択用の一覧が一致したか。

確認できた範囲で、普段の仕事を依頼できます。保留や未確認の項目があれば、それに依存する部分だけを待ちます。見送り・不要と決めたものは、未完了の作業として残しません。

### 読み込みと自動選択の受け入れ確認

ここからは、開発・検証担当者が動作を検証済みと報告するための確認です。利用者全員が通常利用の前に、新しい会話や環境を用意して実施する手順ではありません。

0.2の実際のメインdotでの同梱資料の読み込み、同梱スクリプトの実行、スキル名を指定しない依頼での選択、会話や環境をまたぐ継続性は、受け入れ確認が未完了です。ソースの検査と合成テストの成功を、これらの確認結果に置き換えません。移行時に必要な導入済みリソースの確認は、次節の条件に従います。

動作確認を依頼するときは、対象版と確認範囲を決めます。現在の会話で明示的に読めたことと、事前に資料を与えていない通常の依頼で選べたことを分けて報告します。新しいスレッドの表示やアプリの再起動だけで、新しい文脈・クラウド環境を用意できたとも判断しません。

具体的なケースと証拠の条件は[受け入れ確認](../../evals/dot-toolkit/README.md)にあります。確認のためだけにdotをリセットしたり、個別設定を変えたり、定期テストを始めたりはしません。

## 0.1から0.2へ移行する

メインのdotへ「既存のdot-toolkit 0.1設定を0.2へ移行して」と明示的に依頼します。移行は現在のスキル内容と選択範囲を保つ作業で、スキルの最新版への更新は別に扱います。

dotは[同梱の移行手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/migrations/0.1-to-0.2.md)に従い、次の順に進めます。

1. **新しい入口を確認します。** 導入済み0.2の共通指示、必要な参照、検査コードを取得し、許可された範囲で必要な検査を実行します。ソースだけの検査では代用しません。
2. **旧共通指示を保ちます。** 旧`/workspace/AGENTS.md`を、実際に採用したことが分かる公開版と比較します。差分がある、または採用版が不明なら、全文を`/workspace/.codex/AGENTS-migrate-0.1.md`へ上書きせずに保存し、一致を確認します。最新の公開版を比較基準にはしません。
3. **継続する個別指示を選びます。** 退避した文書は、そのまま有効な個別指示にはなりません。どの内容を継続して使うかは利用者が判断し、既存の個別指示との関係を確認して、明示的に承認された内容だけを適用します。
4. **スキルの記録を移します。** 現在のスキルのバイト列と旧INDEXの選択範囲を保ち、新しいINDEXとスキルごとの採用記録を作って照合します。全manifestからの再登録や上流更新は行いません。
5. **確認後に旧ファイルを整理します。** 新経路と必要な内容保存を確認できた対象だけを、承認された方法で整理します。旧手順の編集、未完了の入力、所有者や用途が分からないファイルは、勝手に削除しません。

0.2では共通の`/workspace/AGENTS.md`と`/workspace/.codex/dot-setup.md`を常設しません。ただし、移行が未確認のままファイル名だけを理由に消さないでください。旧指示が読み込み済みの会話に残る場合もあるため、新しい文脈での動作確認はファイル移行と分けます。

## 後から変更するとき

### プラグインを更新する

手動でアップロードしたプラグインは、必要な権限があり、詳細画面にUpload new versionが表示される場合に新しいZIPをアップロードできます。取得元から管理されるプラグインは、その取得元の更新方法に従います。[公式の更新案内](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt)を確認し、更新後はメインのdotで実際に利用できる版を確かめます。

プラグインの更新は、個別指示やクラウドに置いたタスク用スキルの一括更新を意味しません。

### 個別指示やスキルを変える

変えたい対象と内容を伝えます。後から個別ファイルを渡す場合も、適用する範囲を明示すれば、初期設定全体をやり直す必要はありません。

スキル更新では、現在のファイルを以前の採用記録と比べてから、新しい版との差分を確認します。由来の分からない編集は保ち、上書きやハッシュの再計算で差分を消しません。日常の選択対象も、承認した範囲だけ変更します。

### 中断した作業を再開する・同じ版を再現する

再開時は、現在の配置と記録を確かめ、固定済みのコミットで未完了部分だけを進めます。再試行を理由に最新版へ切り替えません。正確な再現には、採用記録、固定コミット、必要なローカル変更の内容が必要です。ハッシュだけでは失われた編集を復元できません。

これらの操作は[スキル保守手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/skills-maintenance.md)に沿って行います。新しいバックアップ・ログ管理の仕組みを一律に作る必要はありませんが、失われるおそれのある編集や再開に必要な内容は、変更前に保ちます。

## 困った場合

- **ZIPはあるがdotで使えない**：ファイル保存・アップロード・インストールを分け、対象アカウントでプラグインが利用可能か確認します。
- **個別ファイルが初めからない**：その追加指示なしで通常の仕事を続けられます。空ファイルや代替設定を作る必要はありません。
- **読めない、使っていたファイルが消えた**：未作成とは区別し、その資料に依存する部分を止めます。無断の再構築や別経路でのアクセス回避はしません。
- **更新が反映されたか分からない**：プラグインの版、開発ソース、クラウドのスキルコピー、管理記録のどれを変更したか確かめます。
- **検査で不一致が出た**：既存の編集を保ち、差分の由来を調べます。検査ツールは不一致を報告するだけで、ファイルを書き換えません。[検査結果の意味](instructions.md#読み取り専用の検査)を参照してください。
