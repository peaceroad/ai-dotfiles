# dot-toolkitのインストール・初期設定・変更

まずChatGPT Webでプラグインをインストールし、メインのdotから共通スキルを読めることを確認します。個別指示や自作スキルをファイルで管理したい場合だけ、続けてdotのクラウドを設定します。

0.1を利用中の場合は、新しいプラグインへのアクセス確認後に[移行の節](#01から02へ移行する)へ進んでください。既存ファイルを新規設定として置き換えません。

## 1. ChatGPT Webでプラグインをインストールする

### パッケージを用意する

配布者からdot-toolkitのZIPまたは共有プラグインを受け取ります。共有プラグインを使う場合、ZIPの作成は不要です。

ソースからZIPを作る場合は、配布者が指定したタグまたはコミットを使います。指定がなければ、この手順書を含むコミットを選びます。`plugin.json`の`version`が`0.2.0`であることを確かめ、[plugins/dot-toolkit/](../../plugins/dot-toolkit/)の`plugin.json`、`README.md`、`skills/`をZIPの直下へ入れます。リポジトリ全体や、外側の`dot-toolkit/`フォルダーは含めません。

Gitのチェックアウトから作る場合は、選んだコミットへ切り替え、リポジトリのルートで次を実行できます。

```sh
git rev-parse HEAD
git show HEAD:plugins/dot-toolkit/plugin.json
git archive --format=zip --output=../dot-toolkit-0.2.0.zip HEAD:plugins/dot-toolkit
```

最初の2コマンドで対象コミットと版を確認し、最後のコマンドで親ディレクトリへZIPを作成します。同名ZIPがあれば、実行前に出力名を変えてください。含まれるのはコミット済みの内容で、未コミットの編集は入りません。生成ZIPはコミットせず、個別指示や実際の管理記録を混ぜないでください。

### Webで追加・インストールする

ChatGPT Webを開き、dotを使うアカウントとワークスペースを選びます。

- **ZIPを使う場合**：利用できるプラグインアップロード機能から追加します。アップロード権限のあるワークスペース管理者向けの経路は、管理コンソールのPlugins → Add → Upload pluginです。
- **共有プラグインを使う場合**：ChatGPTのPluginsから、共有された`dot-toolkit`を開きます。

プラグインの詳細を開き、Install pluginが表示される場合は選択します。アップロードできたことに加えて、対象アカウントでインストール済み・利用可能になったことを確認してください。機能や必要な権限はアカウント・ワークスペースによって異なります。項目が見つからない場合は、[公式のプラグイン案内](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt)で提供条件を確認します。

チャットへのZIP添付、ライブラリへの保存、クラウドへの展開だけでは、プラグイン導入は完了しません。このガイドはdot-toolkitの導入経路としてWebを案内しています。すべてのプラグインの導入先をWebに限定するものではありません。

### メインのdotから確認する

インストール後、メインのdotへ次のように依頼します。

> インストールしたdot-toolkitのdot-guidelinesを読めるか確認して。

実際の導入済み共通スキルと、今回の作業に必要な同梱資料を確認します。版の情報が得られる場合は、意図した`0.2.0`かも確かめます。リポジトリのソースや、ローカルCodexにある同名プラグインの確認では代用しません。

読めない場合は、アカウント・ワークスペース、プラグインの状態、確認できた版を調べます。原因が分からないまま再インストールを繰り返したり、端末間の同期を前提にしたりしません。一度確認できたら、版や利用環境の変更、読取失敗などがない限り、同じ導入確認を依頼のたびに繰り返す必要はありません。

## 2. 必要なクラウド設定を依頼する

個別指示やタスク用スキルをファイルで管理したい場合は、「dot-toolkitで初期設定して」と依頼します。dotは[同梱の手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/setup.md)で既存ファイルを確認し、必要な設定だけを進めます。別の`dot-setup.md`を添付する必要はありません。共通指示だけを使う場合は、この設定を省けます。

### 個別入力を選ぶ

まだ判断が決まっていない場合は、次の2つについて、それぞれ今渡す・後で渡す・今回は不要を選びます。

- **個別指示**：利用者固有の作業条件や、特定の仕事で参照する文書。
- **追加スキル候補**：次の共通候補以外に検討したいスキル。

一方が不要でも、もう一方まで不要にはなりません。後回しや提供待ちの内容は、再開に必要な判断だけを非公開で残します。状態だけを書く空の指示ファイルは作りません。入力が保留でも、それに依存しない作業は進められます。

### 使うスキルを選ぶ

初期設定では、次の4スキルを共通候補として案内します。すべてを採用する必要はありません。

- `agent-workflow-design`：継続・反復する仕事の役割分担、待機、再開、終了を設計する。
- `prompt-design`：モデルへ渡す指示を設計・レビュー・改訂する。
- `agent-improve`：スキルやプラグインを比較評価し、改善実験を行う。
- `plugin-creator-agent-plugins`：プラグインを作成・検証・移行・パッケージ化する。

dotが用途、取得元、提案する版、必要な環境、現在の配置と変更内容を示してから、配置するものを選びます。共通候補と個別の追加候補は、別々に追加・更新の範囲を承認します。すでにその範囲を承認していれば、確認をやり直しません。どちらも見送れます。「追加なし」は既存スキルの更新・削除を意味しません。

承認したスキルは、参照・スクリプト・素材を含むフォルダー一式をdotのクラウドへコピーします。これがこの手順でいう「スキル配置」です。最初のdot-toolkitのインストールや、ChatGPTへのスキル登録とは別の作業で、アプリ側の既存スキルを自動でコピー・更新しません。未選択の依存スキルやランタイムが必要なら、その扱いを別途確認します。保存場所は[ファイル構成](instructions.md#クラウドの基本配置)にあります。

## 3. 普段の仕事を依頼する

共通スキルを読めることと、依頼に必要な設定を確認できたら、普段の仕事を頼めます。たとえば`prompt-design`を配置した場合は、「この依頼文の曖昧なところを減らして」と伝えます。スキル名や場所を毎回指定する必要はありません。

初期設定を依頼した場合は、dotの完了報告で、次を確認します。

- **プラグイン**：メインのdotから共通スキルと必要な同梱資料を読めたか。
- **個別入力**：何を適用し、何を提供待ち・後回し・不要としたか。
- **スキル配置**：配置した内容が採用記録に一致し、選択一覧が承認した範囲を保っているか。

見送り・不要と決めた設定を待つ必要はありません。保留や未確認の項目があれば、それに依存する作業だけを待ちます。これらは設定時の確認であり、普段の依頼で繰り返すチェックリストではありません。

## 0.1から0.2へ移行する

メインのdotへ「既存のdot-toolkit 0.1設定を0.2へ移行して」と明示的に依頼します。移行では現在のスキル内容と選択範囲を保ち、最新版への更新は別に扱います。

dotは[移行手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/migrations/0.1-to-0.2.md)に従って、次の作業を行います。

1. **新しい入口を確認する。** 導入済み0.2の共通指示、必要な参照、検査コードを取得し、許可された範囲で必要な検査を実行します。ソースだけの検査では代用しません。
2. **旧共通指示を保つ。** 旧`/workspace/AGENTS.md`を、実際に採用したことが分かる公開版と比較します。差分がある、または採用版が不明なら、全文を`/workspace/.codex/AGENTS-migrate-0.1.md`へ上書きせず保存して一致を確認します。比較元を最新公開版で代用しません。
3. **継続する個別指示を選ぶ。** 退避した全文は保存用資料です。そのまま有効な個別指示にはせず、利用者が選び、明示的に承認した内容だけを既存の個別指示との関係を確認して適用します。
4. **スキルの記録を移す。** 現在のファイルと旧INDEXの選択範囲を保ち、新しいINDEXとスキルごとの採用記録を作って照合します。未選択スキルの追加や上流更新は行いません。
5. **確認後に旧ファイルを整理する。** 新経路と内容の保全を確認できた対象だけを、承認された方法で整理します。旧手順の編集、未完了の入力、所有者や用途が不明なファイルは残します。

0.2では共通の`/workspace/AGENTS.md`と`/workspace/.codex/dot-setup.md`を常設しません。ただし、移行が未確認のまま削除することはありません。旧指示は読込み済みの会話に残り得るため、新しい文脈での動作確認とファイル移行は分けます。

## 後から変更するとき

### プラグインを更新する

手動アップロードしたプラグインは、必要な権限があり、詳細画面にUpload new versionが表示される場合に新しいZIPをアップロードできます。取得元から管理されるプラグインは、その更新方法に従います。[公式の更新案内](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt)を確認し、更新後にメインのdotで利用できる版を確かめます。

この更新で、個別指示やクラウドのタスク用スキルを一括更新することはありません。

### 個別指示やスキルを変える

変えたい対象と内容を伝えます。個別指示だけを保存・変更する場合は、初めてでも、その指示と参照先だけを比較・適用し、読み戻して確認します。初期設定全体やスキル候補の選択を行う必要はありません。

スキル更新では、現在のファイルを以前の採用記録と比較してから、新しい版との差分を確認します。由来が分からない編集は上書きせず、検査を通すための再ハッシュもしません。選択一覧への追加・除外は、承認した範囲に限ります。

選択一覧だけを変える場合は、スキル本体や採用版を変えません。たとえば一覧から外すだけなら、そのスキルを再取得・修復する必要はありません。

### 中断した作業を再開する・同じ版を再現する

現在の配置と記録を確認し、固定済みのコミットで未完了部分だけを進めます。再試行を理由に最新版へ切り替えません。同じ内容を再現するには、採用記録、固定コミット、必要なローカル変更の内容が必要です。ハッシュだけでは失われた編集を復元できません。

[スキル保守手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/skills-maintenance.md)は、バックアップやログの管理基盤を一律に要求しません。ただし、失われるおそれのある編集と、再開に必要な内容は変更前に保ちます。

## 困った場合

- **ZIPはあるがdotで使えない**：保存・アップロード・インストールのどこまで済んだか、対象アカウントで利用可能か確認します。
- **個別ファイルが初めからない**：追加指示に依存しない仕事は続けられます。空ファイルや代替設定は不要です。
- **読めない、使っていたファイルが消えた**：未作成とは区別し、その資料に依存する部分を止めます。無断で再構築したり、別経路でアクセス拒否を回避したりしません。
- **更新が反映されたか分からない**：プラグイン、開発ソース、クラウドのスキルコピー、採用記録のうち、どれを変更したか確かめます。
- **検査で不一致が出た**：編集を保ち、差分の由来を調べます。検査ツールはファイルを書き換えません。[検査結果の意味](instructions.md#読み取り専用の検査)も参照してください。

## 読み込みと自動選択の受け入れ確認

ここは、開発・検証担当者が「動作を検証済み」と報告するための確認です。通常利用の前に、利用者全員が新しい会話や環境を用意して試験する必要はありません。

実際のメインdotでの同梱資料の取得・スクリプト実行、スキル名を指定しない依頼での選択、会話や環境をまたぐ継続性は、それぞれ別に観測します。0.2では受け入れ確認が未完了で、ソース検査や合成テストの成功では補えません。移行に必要な導入済みリソースの確認は、[移行の節](#01から02へ移行する)の条件を満たす必要があります。

試験の前提と証拠の条件は[受け入れ確認](../../evals/dot-toolkit/README.md)にあります。確認のためだけにdotをリセットしたり、個別設定を変更したり、定期テストを始めたりはしません。
