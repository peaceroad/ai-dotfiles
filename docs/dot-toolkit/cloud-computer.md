# クラウドコンピュータを使う

dotにコマンドの実行やブラウザー・アプリの操作を頼むとき、どの方法なら結果を確認できるかを判断するためのガイドです。ターミナルと画面操作では、見える内容や使える操作が異なる場合があります。

ファイルの置き場所や残し方は、[クラウドのファイル管理](cloud-workspace.md)を参照してください。

## 作業する環境を確かめる

dot自身のクラウド、利用者のPC、接続先の外部サービスは、それぞれ別の作業先です。メインのdotという役割名や`/workspace/`などのパスが一致することだけでは、環境、アクセス範囲、操作の許可は確定しません。作業を始める前に、その仕事へ割り当てられた作業ディレクトリと、提供されているツール、読み書きできる範囲を確認します。

### 設定ファイルへのアクセスを説明するとき

たとえば`~/.codex/config.toml`については、ファイルの存在、読み取り、書き込み、設定の反映を別々に確認します。`~`が指すホームディレクトリは実行環境によって異なるため、利用者のPCとクラウドで同じファイルを指すとは限りません。ファイルを読めても変更できるとは限らず、変更できても、その設定を現在のアプリやサービスが読み込むとは限りません。

アクセス可否を説明するために、認証情報を含み得る設定内容を広く収集したり、文書へ転載したりする必要はありません。確認した操作と対象だけを示し、未確認の読み書きや設定反映は未確認として扱います。

## ターミナルと画面操作を使い分ける

クラウドでの作業には、ターミナルでファイルやコマンドを扱う方法と、提供されている画面操作ツールでブラウザーやアプリを扱う方法があります。どちらが使えるか、何を確認できるかは、その時点で提供されたツールとアクセス範囲によります。

- **ターミナルでの確認**：読み取れるファイルの内容、パス、コマンドの実行結果などを確認します。コマンドが成功しても、アプリの画面に結果が表示されたことまで確認したとはいえません。
- **画面上での確認**：ブラウザーやアプリに現在表示されている内容、画面上で行った操作とその結果を確認します。画面に表示されたことだけで、ターミナルから同じファイルを読めることや、別の接続先へアクセスできることは分かりません。

たとえば、リポジトリの文書を編集する仕事では、ターミナルで対象ファイルと差分を確認できます。一方、「ブラウザーで見たときに表示が崩れていないか」を確かめる仕事では、生成ファイルを読むだけでなく、利用可能なブラウザーで実際の表示を確認する必要があります。

チャットの情報やコマンドの結果だけでは分からなくても、許可されたクラウドの画面操作で、アプリの版情報、表示、操作結果を確認できる場合があります。まだ観測していないことだけで、製品として不可能とは判断しません。利用者が画面で確認した結果を伝えた場合も、dot自身が画面で確認した結果とは分けます。

違いがあれば、「どの環境の、どの方法で、何を確認したか」を分けて伝えます。確認していない内部の仕組みや、制限の理由を推測して説明しません。

### 操作方法を切り替えるとき

作業ディレクトリは、コマンド実行ツールや画面上のターミナルなど、操作方法ごとに確認します。新しく開いたGUIのターミナルが、その仕事へ割り当てられたディレクトリから始まるとは限りません。ファイル操作の前に現在位置を確かめ、必要なら確認済みの作業先へ移ります。

画面操作では、すでに開いていたタブやウィンドウを保ちます。片付ける場合も、自分の作業で一時的に開いたものだけを閉じ、既存の作業状態を巻き込まないようにします。

## ツールの有無と、使える範囲を分けて確かめる

ツールの確認では、次の段階を区別します。必要な確認の深さは、依頼された成果物に合わせます。

1. **コマンドやパッケージが見つかる**：実行ファイルの場所やライブラリの所在を確認した段階です。別名のコマンドで提供される場合もあるため、一つの名前が見つからないだけで、そのソフトウェア全体がないとは判断しません。
2. **起動・読み込みができる**：バージョン表示やライブラリの読み込みが成功した段階です。版番号を取得できないことと、ライブラリを読み込めないことも分けます。
3. **必要な処理が動く**：小さな入力で生成・変換・計算などを試し、結果を読み戻した段階です。成功した処理と入力の範囲を記録します。
4. **成果物の品質を確認できる**：依頼に必要な内容、表示、レイアウト、再計算などを確認した段階です。単純なファイル生成が成功しても、日本語の表示や複雑な文書の互換性まで確認したことにはなりません。

コマンドが存在することは、そのコマンドによるインストール、外部通信、設定変更などの許可を意味しません。実行可否と操作の許可を確かめてから、必要な範囲を検証します。

## Webサイトのログインを扱う

以下は、2026年10月11日に確認したOpenAI公式資料に基づく説明です。dotのクラウドブラウザーと利用者のPCのブラウザーは、別のログイン状態を持ちます。PC側でログインしても、クラウド側へは引き継がれません。有効なWebサイトのセッションは、ログアウトするかサイト側で期限切れになるまで、後の仕事でも再利用できます。[コンピュータとアプリの接続ガイド](https://learn.chatgpt.com/docs/dots/computers-and-apps#sign-in-to-a-website)

対応するログインでは、専用の安全なフォームに認証情報を入力します。情報はモデルに見せず、ブラウザー環境へ直接送られます。この保護は、チャットや文書へ別途書いたパスワードや、プラグイン経由で渡したパスワードには適用されません。認証コードの提供や、セキュリティ確認のための手動操作が必要な場合もあります。[プライバシー・セキュリティ・安全性FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)

- **セッションと保存済みログインを分ける**：Save to Passwordsが提示された場合、保存は任意です。有効なセッションの継続利用と異なり、保存済みログインを使って新たにサインインする際は利用者の確認が必要です。[ログインの保存と再利用](https://learn.chatgpt.com/docs/dots/computers-and-apps#saving-and-reusing-a-login)
- **接続アプリの権限を分ける**：プラグイン経由のアクセスは、接続したアカウント、許可された操作、実行環境で決まります。Webサイトへのログインや連絡手段の追加だけで、接続アプリの権限が増えるわけではありません。[アプリの接続](https://learn.chatgpt.com/docs/dots/computers-and-apps#connect-apps)

## 利用できない場合の進め方

通常のツール選択では、依頼された結果を確認できる、利用可能で許可された方法を選びます。一方、ある操作や対象へのアクセスを拒否された場合は、同じ操作を別の経路で通そうとしません。依存する部分を止め、何が確認できず、再開に何が必要かを伝えます。この区別は、[共通指示の読取失敗・アクセス拒否の扱い](guidelines.md)と[環境確認手順](../../plugins/dot-toolkit/skills/dot-guidelines/reference/computer-checks.md#access-the-correct-resources)に沿うものです。

ツールや入力が不足している場合は、不足分と未確認の結果を伝えます。追加の接続や権限が必要なときは、対応している方法と必要な承認を確認します。

## 結果を受け取るときに確認すること

- **作業した場所**：dot自身のクラウドか、利用者のPCか、外部サービスか。
- **確認した方法**：ファイルの読み戻し、コマンドの実行、画面上の表示や操作のうち、何を使ったか。
- **確認できた結果**：どの対象と範囲を確認し、何が未確認のままか。

製品そのものの機能と利用条件は、OpenAIの[dotの始め方](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)と[安全性FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs)、作業時に提供されたツールで確認します。
