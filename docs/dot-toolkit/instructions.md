# dot-toolkitの共通指示とファイル構成

このページは、インストール後の読み込み方や、dotのクラウドに置くファイルを確認したい人向けのリファレンスです。初めて使う場合は、先に[インストールと初期設定](setup.md)へ進んでください。

## プラグインに含まれるもの

0.2の共通指示は、プラグイン内の[dot-guidelines](../../plugins/dot-toolkit/skills/dot-guidelines/SKILL.md)にあります。別の共通指示ファイルへ転送するだけのローダーではなく、このスキル自体がメインのdotの読み込み方・応答・作業場所の方針を持ちます。

設定や保守に必要な詳しい手順は、次の同梱リファレンスへ分けています。通常の依頼ですべて読む構成ではありません。

| 参照先 | 読む場面 |
| --- | --- |
| [setup.md](../../plugins/dot-toolkit/skills/dot-guidelines/reference/setup.md) | 明示された初期設定、個別指示の保存・変更 |
| [computer-checks.md](../../plugins/dot-toolkit/skills/dot-guidelines/reference/computer-checks.md) | 環境や配置の点検、具体的なアクセス・実行上の問題、検査結果の確認 |
| [skills-maintenance.md](../../plugins/dot-toolkit/skills/dot-guidelines/reference/skills-maintenance.md) | スキルの追加・更新、選択対象の変更、比較・再現、中断した保守の再開 |
| [migrations/0.1-to-0.2.md](../../plugins/dot-toolkit/skills/dot-guidelines/reference/migrations/0.1-to-0.2.md) | 0.1の共通ファイルや管理記録からの移行 |

ほかに、読み取り専用の検査スクリプト、プラグインのmanifest、英語のREADMEを配布します。個別指示、タスク用スキル、MCPサーバー、hooksは同梱しません。

## 通常の依頼で読むもの

共通指示を使うメインのdotは、次の順に仕事に必要な資料を選びます。

1. 個別指示の`/workspace/.codex/AGENTS-private.md`があれば全文読み、今回に関係する条件と参照先を確認します。
2. `/workspace/.agents/skills-state/INDEX.md`があれば読み、用途に合うスキルを選びます。クライアントが提供する利用可能なスキルのdescriptionも使います。
3. 選んだ`SKILL.md`と必要な参照資料を全文読んでから、それらに依存する作業を進めます。

INDEXはスキル選択のための一覧で、実行時の条件を確認する本文の代わりにはなりません。説明の一部や検索結果だけで全文を読んだことにせず、出力が途中で切れたら末尾まで取得します。現在の文脈で全文を確認済みの指示を、確認のためだけに重ねて読む必要はありません。

個別指示とINDEXが初めから未作成でも、追加指示や不明な管理在庫に頼らず作業を続けられます。クライアントから利用できるスキルも引き続き選べます。欠けた任意ファイルを補うための探索・作成・スキル配置や、初期設定の質問は始めません。

一方、読取失敗、アクセス拒否、一覧の破損、以前使っていた指示の消失は、初めから未作成の状態とは違います。選んだスキルや必須参照が欠ける場合も、問題を伝えて依存する部分だけを止めます。通常の依頼を修復の依頼に読み替えたり、拒否されたアクセスを別経路で回避したりしません。

### 個別指示の書き方

`AGENTS-private.md`には利用者固有の指示を直接書けます。別文書へ分ける場合は、読む条件と参照先を示します。たとえば校正時の用語表を、無関係な仕事でも毎回読む資料にはしません。

会話で伝えた好みをすべて転記する必要はありません。アプリのカスタムルールは別に管理し、このファイルへ複製しません。保留中の個別入力も、実際の指示を表すファイルへ状態だけを書き込まず、必要なら非公開の再開記録で扱います。

### 別のエージェントへ仕事を任せるとき

`dot-guidelines`の対象はメインのdotです。通常のCodexタスクや別の担当エージェントへ、共通指示全体を課すものではありません。担当する仕事の目的、対象、必要な条件を渡します。

タスク用スキルは、そのスキルの用途に合えば別のエージェントも利用できます。引き継ぎ時にはスキルの場所を伝え、担当環境で本文と必要な参照を読めることを確認します。親が読んだ内容や同じ絶対パスのファイルが、別環境へ自動で引き継がれるとは考えません。

### 応答の方針

答え・結果・必要な次の行動から伝え、理解に必要な根拠と注意点を残します。明らかな内容の反復、過度な称賛、不要な表を避け、事実・推測・重要な未確認点を区別します。単に短い返答に限定する方針ではありません。

## クラウドの基本配置

次の配置はdot自身のクラウド用です。利用者のPCへの配置や、アプリにインストールしたプラグインの保存先を示す図ではありません。

```text
/workspace/
├── .codex/
│   └── AGENTS-private.md           任意の個別指示・条件付き参照
├── .agents/
│   ├── skills/
│   │   └── <name>/                 採用したスキル一式
│   └── skills-state/
│       ├── INDEX.md                通常の選択に使うスキルの一覧
│       └── manifests/
│           └── <name>.json          各スキルの採用元・ファイルハッシュ
└── shared/
    ├── projects/<project>/         継続する仕事のソース・下書き・成果物
    ├── downloads/                  取得資料・固定版のスナップショット
    ├── tools/                      利用者管理のツール・ランタイム
    └── outputs/<project>/          一時作業から残す確認済み成果物
```

共通指示と共通の設定手順はプラグイン内にあります。0.2では`/workspace/AGENTS.md`と`/workspace/.codex/dot-setup.md`を常設しません。`.codex/`に追加するのは、実際に提供された個別文書や必要な再開記録です。図の任意ファイルやディレクトリを最初からすべて作る必要はありません。

継続する仕事はプロジェクト内でまとめ、一時作業には割り当てられた作業ディレクトリを使います。後で必要な成果物は確認してから保持先へ移します。常に`outputs/`へ複製する必要はありません。`shared`という名前だけで公開範囲や永続性を判断せず、実際の環境で確認します。

### スキル本体・一覧・採用記録の違い

`skills/<name>/`には、参照・スクリプト・素材を含むスキルの完全なコピーを置きます。開発ソースや取得した固定版とは分け、ソースの編集を自動で反映しません。

`skills-state/INDEX.md`は、日常の選択に使うと決めたスキルのカタログです。リンクは`../skills/<name>/SKILL.md`とし、各スキルのfrontmatterを解釈したdescription全文を保持します。説明の各行を`>`で始め、見出しや`---`で項目を区切ります。元のYAML記法をそのまま写すのではなく、引用・折り返し・改行が表す内容を読む必要があります。正確な形式は[INDEXの定義](../../plugins/dot-toolkit/skills/dot-guidelines/reference/skills-maintenance.md#index-contract)にあります。

`manifests/<name>.json`は、そのスキルで採用した版とファイル内容の記録です。INDEXに載せるかどうかの判断とは別なので、`selected`フラグは持ちません。保守時に全manifestからINDEXを再生成すると、意図して外したスキルまで選び直すことになるため、承認された掲載範囲を保ちます。

INDEXがない状態、正しい形式で選択が空の状態、以前の一覧が失われた状態も区別します。このINDEXはChatGPT側の全スキル一覧ではありません。

### 採用manifestの形式

スキルごとのmanifestは`schemaVersion: 1`のJSONです。`name`、取得元を示す`source`の`repository`・`path`・`ref`・`commit`、ファイルごとの`path`・`sha256`を記録します。必要な場合だけ、`localChanges`と`verification`で簡潔な変更・検証情報を添えます。詳細は[manifestの定義](../../plugins/dot-toolkit/skills/dot-guidelines/reference/skills-maintenance.md#per-skill-manifest-schema-1)を参照してください。

この形式はdot-toolkit独自の管理規約です。プラグインの版`0.2.0`、manifestの形式番号、スキルの取得元コミットは、それぞれ別のものを特定します。

ハッシュは、生のバイト列を採用時の記録と比べるために使います。意味、実行権限、所有者、外部依存物、コードの安全性まで証明するものではありません。失われた内容の復元にも使えません。更新前の差分保護と再現の進め方は[変更手順](setup.md#後から変更するとき)にまとめています。

## 読み取り専用の検査

同梱の3スクリプトはNode.js 24以降の標準モジュールだけを使い、JSONで結果を返します。dotが必要な点検や保守で使うためのもので、通常の依頼で定期実行するものではありません。

- `inspect-computer.mjs`：決められた配置と実行ランタイムを確認します。個別指示などの非公開ファイルは存在だけを調べ、内容を読み出しません。
- `check-skill-index.mjs`：INDEXの形式、選択したスキルの記録、リンク、実際の参照先を検査します。YAMLの解釈やdescriptionの意味の一致は判定しません。
- `verify-skill-files.mjs`：指定したスキル、または明示した`--all`について、採用manifestと実際の相対パス・ファイル内容を照合します。内容はバイト単位で比べます。

終了コードは`0`が検査完了・適合、`1`が不一致、`2`が未検証・読取エラーなどです。存在確認は任意ファイルがなくても完了します。INDEXの検査では、未作成は未検証、正しい形式の空の選択は適合です。結果の意味は検査対象に限定します。

スクリプトは書き込み、ネットワーク取得、インストール、修復を行いません。書き込み可否、利用者のPCや外部サービスへの接続、指示の意味、自動選択、永続性は別途確認が必要です。未対応のリンクやファイル種別も無視して合格にしません。

実行時は、インストール済みプラグインのコードと取得元を確認します。テキストでしか取得できない場合の実行用コピーも含め、[検査の手順と結果契約](../../plugins/dot-toolkit/skills/dot-guidelines/reference/computer-checks.md)に従います。リポジトリのソースを実行できたことは、インストール済みリソースを利用できた証拠にはなりません。

## アクセス範囲と権限

指示ファイルは、使えるツールや接続、承認の範囲を増やしません。dot自身のクラウド、利用者のPC、外部サービスを分け、その作業に提供された方法と権限を確認します。読み取り・変更・第三者への共有は、それぞれの条件で判断します。

共通指示・個別指示・スキルは、現在の依頼、指示の優先関係、サービスの制約、アプリの承認手順の下で使います。ファイルへの記載を、コード実行、インストール、外部送信、自動化、権限変更への一括承認にはしません。プラグインのソース修正だけでも、実環境のインストールや移行は始めません。

個別文書、実際のスキル在庫、取得・復元・移行の記録は非公開として扱います。公開リポジトリ、PR、配布ZIP、公開用の検査ログへ持ち込まず、説明や試験には一般化した内容と合成例を使います。生成ZIPもリポジトリへコミットしません。

## 0.2の変更点

0.1では外部の共通指示と添付手順を使っていました。0.2では、それらをプラグインへ集約し、スキル本体から一覧・採用記録を分離しました。単一の大型manifestはスキルごとの小さな記録へ変更し、変更操作をしない検査スクリプトを加えています。

旧公開ソース`dot/AGENTS.md`と`dot/dot-setup.md`は配布対象から除かれ、過去の内容はGit履歴から参照できます。既存環境の扱いは[0.1からの移行](setup.md#01から02へ移行する)を参照してください。これらの設計変更やソース検査だけで、モデルの性能改善や実際のメインdotでの動作を確認したことにはなりません。
