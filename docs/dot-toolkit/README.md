# dot-toolkitの使い方

`dot-toolkit`は、dot自身のクラウドで共通・個別指示とスキルをファイルとして管理する、非公式・実験的な設定・セットアップツールキットです。プラグインに含まれる短いローダーを入口に、クラウドに置いた指示を読み、依頼に必要なスキルを選ぶ構成を試しています。dot本体の設定・権限・記憶の仕組みを置き換えるものではありません。

対象は、継続的に利用するメインのdot会話です。このガイドでは、利用者が構成を理解し、初期設定や変更の範囲を決めるための情報をまとめています。

## 目的に合わせて読む

- **初めて使う**：このページで構成と始め方を確認し、[構築・更新手順の解説](setup.md)へ進みます。
- **共通指示を理解・調整する**：[共通指示と読み込みの解説](instructions.md)で、個別指示との分担、スキルの選び方、応答の方針、基本配置、アクセス範囲を確認できます。
- **設定を変更・再開・再現する**：[構築・更新手順の解説](setup.md#後から変更するとき)で、既存の編集と採用版を保ちながら進める方法を確認できます。

英語の[プラグインREADME](../../plugins/dot-toolkit/README.md)は、配布物に含める導入案内です。実行時の条件は[ローダー](../../plugins/dot-toolkit/skills/dot-guidelines/SKILL.md)、[共通指示の公開テンプレート](../../dot/AGENTS.md)、[構築手順dot-setup.md](../../dot/dot-setup.md)で定めます。この日本語ガイドを、通常の依頼で毎回読む実行指示として追加するものではありません。

## プラグインとクラウドの役割

開発中のエージェントスキルを試したい場合や、Web版への登録を使わずにスキルを利用したい場合に、dot自身のクラウドの`/workspace/.agents/skills/`へファイルとして配置できます。`dot-toolkit`は、その配置と参照先の案内を整え、毎回スキルの場所を説明する手間を減らします。

クラウドへのファイル配置と、Web上の対応機能によるアプリへの導入・登録は別の方法です。どちらを先に使うかを定めるものではなく、配置しただけでアプリに登録されたり、自動的に見つけられたりするとは限りません。Web導入済みのスキルを自動で重ねてコピーすることもありません。

パッケージには、`plugin.json`、`skills/dot-guidelines/SKILL.md`、`README.md`の3ファイルを含めます。`dot-guidelines`が、共通指示を読む短い入口です。タスク用のスキル、個別指示、MCPサーバー、hooksは同梱しません。

日常の作業で読む共通指示は、クラウド側の`/workspace/AGENTS.md`で管理します。個別指示や採用するスキルは利用者ごとに変わるため、公開パッケージから分離して、クラウド側で扱います。プラグインを導入しただけで、それらのファイルが作られたり、候補スキルが配置されたりするわけではありません。

通常の依頼では、必須の共通指示を読み、個別指示と管理スキルのINDEXは存在する場合に読みます。任意の2ファイルが未作成でも、その追加指示や不明な管理在庫に頼らず作業を続け、代替ファイルの探索・作成やスキルの導入はしません。クライアントから利用できるスキルは、INDEXがなくても選べます。選んだスキルと必要な参照資料は、依存する作業の前に全文読みます。読取失敗や利用済みファイルの消失は未作成と区別します。詳しくは[読み込みの流れ](instructions.md#通常の依頼で読むもの)を参照してください。別のエージェントに仕事を任せる場合の指示とスキルの扱いは、[引き継ぎの説明](instructions.md#別のエージェントへ仕事を任せるとき)にまとめています。

## 初期設定を始める

1. Agent Plugins v1とAgent Skillsに対応するクライアントで、`dot-toolkit`を導入する。
2. [dot-setup.md](../../dot/dot-setup.md)を用意し、メインのdot会話へ添付する。
3. 「この手順で初期設定して」と明示的に依頼する。

`dot-setup.md`はプラグインとは別に用意します。開発用PCで管理しているファイルを添付してもかまいません。この手順は、プラグインZIPを特定のWebサイトからダウンロードする運用を要求しません。

個別指示や追加スキル候補は、それぞれ今渡す・後で渡す・今回は不要を選べます。スキルの追加・更新は、共通候補と追加候補を分けて確認・承認します。共通候補4スキルをすべて導入することは、開始条件ではありません。

既存のファイルや編集がある場合は、先に差分を確認します。個別入力の回答・提供待ち・後日提供・明示的に不要・提供済みは、共通指示の取得元情報とともに非公開の構築記録へ残し、状態だけの個別指示ファイルは作りません。保留中でも、具体的な依存関係のない作業は進められます。選択と完了の扱いは[構築手順の解説](setup.md)にまとめています。

## 開発中のプラグインを試す

dotでプラグインを作成・修正し、動作確認用のZIPが必要な場合は、チャットからダウンロードできる形で提供できるようにします。ZIPには公開可能なプラグインファイルだけを含め、個人設定や非公開情報は含めません。生成したZIPはリポジトリにコミットせず、チャットで受け渡します。

## 作業場所とアクセス範囲

この構成はdot自身のクラウドを対象にします。基本配置は、共通指示を`/workspace/AGENTS.md`、個別指示と手順を`/workspace/.codex/`、管理するスキルを`/workspace/.agents/skills/`、継続する仕事や取得資料を`/workspace/shared/`内の用途別ディレクトリに置きます。[配置図とファイルの分担](instructions.md#クラウドの基本配置)を参照してください。

利用者のPCや外部サービスは別の作業先です。指示ファイルを置いてもアクセス権は増えず、その作業で使えるツール、接続、承認の範囲を確認します。ディレクトリ名だけで公開範囲や永続性を判断しません。詳しくは[アクセス範囲と権限](instructions.md#アクセス範囲と権限)を参照してください。

## 完了の見方

共通設定、個別入力、各グループのスキル選択について、完了・保留・不要を分けて確認します。保存したファイルの照合、プラグインの有効化、実際の読み込みや動作、保存内容の保持は、それぞれ別の確認です。

公開ファイルの構成・整合性と評価用コードの動作は検査済みですが、実際のメインのdot会話での自動選択や、会話・環境をまたぐ継続性は十分に検証できていません。パッケージ検査の成功だけで、自動読み込みや保存内容の保持を確認したとは扱いません。[完了の確認と困った場合](setup.md#完了を確認する観点)で、どの結果を確かめるか整理できます。
