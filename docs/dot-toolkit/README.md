# dot-toolkitの日本語ガイド

`dot-toolkit`は、いつも守ってほしい指示や自作・開発中のスキルの場所を、dotへ毎回説明する手間を減らすための、非公式・実験的なプラグインです。共通スキル`dot-guidelines`が、継続的に使うメインのdotへ、個別指示の読み方と依頼にあうスキルの選び方を伝えます。

通常のファイルの検索・作成・ダウンロード・編集・整理や保存先の選択でも、メインのdotは共通指示を使います。既存のプロジェクト構成を尊重して作業します。

スキルを含むプラグインは、フォルダー構成ごとdotのクラウドで管理できます。プラグインに含まれるスキルのうち、普段使うものだけを選べます。0.2で配置した単体スキルも、そのまま使えます。

利用者固有の指示や追加プラグインは同梱せず、必要なものだけをdotのクラウドへ追加します。ChatGPTで通常行うスキル・プラグインの導入も、引き続き使えます。

## 目的にあわせて読む

- **初めて導入する**：[インストールと初期設定](setup.md)。ChatGPT Webでの導入、dotからの確認、必要なクラウド設定を順に進めます。更新や0.1からの移行への案内もあります。
- **ターミナルや画面で作業する**：[クラウドコンピュータを使う](cloud-computer.md)。作業先と操作方法を選び、何を確認できたかを分けます。
- **仕事のファイルを作る・保存する・整理する**：[クラウドのファイル管理](cloud-workspace.md)。継続するプロジェクトと一時作業の置き場所、成果物の残し方を説明します。
- **スキルやプラグインを追加・更新する**：[スキルとプラグインの管理](skills-management.md)。配置した内容、普段使うスキルの一覧、採用版の記録と検査を説明します。
- **dotへ渡す共通指示を詳しく読む**：[共通指示の日本語訳と解説](guidelines.md)。`SKILL.md`を冒頭から順に訳し、補足を分けて示します。

## 使い始める流れ

1. dotを使うアカウントとワークスペースで、ChatGPT Webからdot-toolkitをインストールします。ZIPをチャットへ添付したり、クラウドへ展開したりするだけでは導入は完了しません。
2. メインのdotへ「インストールしたdot-toolkitのdot-guidelinesを読めるか確認して」と依頼します。ローカルCodexやリポジトリの確認では代用しません。
3. 個別指示や追加スキルをクラウドで管理したい場合だけ、「dot-toolkitで初期設定して」と依頼します。候補は用途と変更内容を見て選べ、すべてを採用する必要はありません。
4. 今回の仕事に必要な設定を確認できたら、仕事そのものを依頼します。たとえば`prompt-design`を普段の選択対象にした場合は、「この依頼文の曖昧なところを減らして」と頼めます。

個別指示と追加スキル候補は、それぞれ今渡す・後で渡す・今回は不要を選べます。確認済みの版や環境に変更がなければ、導入確認や初期設定を依頼のたびに繰り返しません。

## 適用範囲と確認できていないこと

共通指示の対象はメインのdotです。通常のCodexタスクや別の担当エージェントへ、そのまま適用するものではありません。このプラグインはdot本体の設定・権限・記憶を置き換えず、利用者のPCや外部サービスへのアクセス権も増やしません。個別指示や実際のスキル在庫は非公開として扱います。

クラウドへのファイル配置、Webでのインストール、MCP通信試験、実際のdotの会話でのツール利用は、それぞれ別の確認です。MCPを含むパッケージを扱う場合は、[ファイルと実行の区別](skills-management.md#mcpのファイルと実行を分ける)を参照してください。任意の[スキル差分比較サンプル](../../examples/skill-diff-plugin/README.md)もありますが、初期設定には不要です。

0.4での暗黙のスキル選択と継続性は、実際のメインdotでの受け入れ確認が未完了です。確認条件は[受け入れ確認](setup.md#読み込みと自動選択の受け入れ確認)を参照してください。
