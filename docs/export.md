# Export guide

`export.js`は、ホームディレクトリにあるファイルを、公開用ファイルとして同じ相対パスでこのリポジトリの`home/`へ同期するためのスクリプトです。外部パッケージには依存しません。

このガイドの手順には、リポジトリの検証要件に合わせてNode.js 24以降を使います。`npm run check:export`は、実際のホームを対象に公開用エクスポートを検査します。リポジトリ全体の`npm run check`ではエクスポートを合成ホームで検証し、ほかのテストも実行するため、WindowsではPowerShell 7（`pwsh`）も必要です。

## コピー対象を設定する

コピー対象は`export.yaml`の`paths`に記述します。各パスはホームディレクトリを基準にした相対パスで、コピー先ではリポジトリの`home/`を基準にします。

たとえば、次の指定では`~/.codex/AGENTS.md`をリポジトリの`home/.codex/AGENTS.md`へコピーします。

```yaml
paths:
  - .codex/AGENTS.md
```

ファイルとディレクトリのどちらも指定できます。ディレクトリを指定した場合は、コピー元からなくなったコピー先のファイルも削除して、ディレクトリ内部を同期します。ファイルを指定した場合は、そのファイルだけを追加または更新します。`export.yaml`には、公開用として管理する対象だけを追加してください。重複するパスや、一方が他方を含むパスは指定できません。

`.agents/ai-dotfiles/skill-links.json`だけは、ホーム側のファイル全体をそのままコピーしません。各リンクの参照先を展開し、パスの存在する部分を実体パスに解決したうえで、このリポジトリ内を指す宣言だけを公開用ファイルへ書き出します。参照先がまだ作成されていなくても宣言は残せますが、リポジトリ外へ転送される参照先は除外します。既存のシンボリックリンクがリンク切れの場合や、参照先の所在を確認できない場合はエラーにします。ホーム側では複数の開発リポジトリを一括管理できますが、公開用の`skill-links.json`には別リポジトリの名前や配置を含めません。

## ファイルの一部だけを書き出す

テキストファイルに次のマーカーが対で含まれている場合は、その区間と隣接するコメントブロックだけを書き出します。

```text
# Shared settings start here.
...
# Shared settings end here.
```

現在の`home/.codex/config.toml`は、この仕組みでローカル専用設定を除外しています。開始・終了マーカーが対応していない場合や、マーカーが不正に入れ子になっている場合はエラーになります。

## 書き出し前の検査

コピー前には、次のような個人情報・機密情報の候補を検査します。

- 機密性の高いファイル名
- ローカルのユーザー名とホームディレクトリのパス
- 一般的なAPIキー、アクセストークン、秘密鍵、パスワードのパターン

正確に`# ENV:`または`# NOTE:`で始まるコメント行では、ローカルのユーザー名を意図的な記述として許可します。その行でも、ユーザー名以外の検査は継続します。

バイナリファイルはファイル名だけを検査し、内容は検査しません。また、この検査は誤公開を完全に防ぐものではありません。書き出したファイルは必ず人が確認してください。

## 使い方

コピー方向はホーム側からリポジトリ側です。リポジトリ内の公開用コピーや改稿案を編集しても、ホーム側の設定は更新されません。改稿を採用する場合は、先にその内容をホーム側へ反映してください。反映前に`npm run build`を実行すると、公開用コピーはホーム側の旧内容で上書きされます。

リポジトリのルートで、最初にドライランを実行します。コピー予定、削除予定、検査結果が表示され、ファイルは変更されません。

```powershell
npm run check:export
```

問題がなければ、ファイルを書き出します。`npm run build`でも変更前に同じ検査を実行し、問題が見つかった場合はコピーも削除も行いません。削除対象は、`export.yaml`で指定されたコピー先ディレクトリの内部に限定されます。コピー元のファイルは変更しません。

```powershell
npm run build
```

最後に、追加・更新されたファイルを確認します。

```powershell
git status --short
git diff
```

`git diff`に表示されるのは追跡済みファイルの差分だけです。未追跡ファイルは個別に開いて内容を確認してください。

## コピー先と失敗時の扱い

コピー先の基準は、実行する`export.js`の親ディレクトリを実体パスに解決したリポジトリです。リポジトリへのシンボリックリンク経由で起動しても、この基準は変わりません。一方、コピー先の`home/`から対象までの途中や対象内にシンボリックリンクがある場合は、空ディレクトリだけを同期する場合も処理を中止します。全対象の検査を変更前に行い、作成・置換・削除の直前にもコピー先を再確認します。

コピー元の選択対象や、その配下のシンボリックリンクは従来どおり拒否します。コピー元の祖先にあるリンクは許容しますが、実体パスに解決した選択対象とリポジトリの`home/`が一致するか、どちらかが他方を含む場合は拒否します。公開用コピーをコピー元として扱うことで、元データまで更新・削除してしまうのを防ぐためです。

変更のあるファイルは、コピー先と同じディレクトリに一時ファイルを排他的に作成し、書き終えて閉じてからrenameで置換します。既存ファイルの内容を直接切り詰めないため、コピー先がコピー元や別ファイルへのハードリンクでも、そのリンク先の内容は変更しません。一時ファイルへの書き込みや置換に失敗した場合、置換前のコピー先ファイルは残ります。

同期全体は一括で元に戻せる処理ではありません。途中の入出力エラーでは、それまでに成功した更新・削除やディレクトリ作成が残る場合があります。通常のエラー時は未使用の一時ファイルを削除しますが、その削除も失敗すると`.export-*.tmp`が残ります。エラーと`git status --short`で状態を確認し、原因を解消してから再実行してください。

これらの検査は、検査と操作の間に別プロセスがパスを差し替える競合を完全には防ぎません。実行中はコピー元・コピー先を変更しないでください。バインドマウントなど、シンボリックリンク以外の仕組みで同じディレクトリを別パスに見せる構成は検出対象外です。敵対的な同時差し替えや、電源断時の永続性を保証するものではありません。

## ターミナル出力の見方

`Export plan`または`Dry-run export plan`は、コピー対象の計画を表示している段階です。この表示だけでは、まだファイルが書き換えられたとは限りません。

計画に表示するコピー元は`~`、コピー先はリポジトリ相対パスで表記し、ユーザー名を含む絶対パスは表示しません。

スキャンが問題なく完了すると、`No potential issues found.`が表示され、その後にドライランの案内または書き出し結果が続きます。個人情報・機密情報の候補が見つかった場合は、`Export aborted: ... no files were changed.`と表示され、コピーも削除も行われません。表示された対象を修正してから、同じコマンドを再実行してください。

対話型ターミナルでは、計画、成功、警告、停止を色で区別します。ログ保存や色に対応していない環境では自動的に色を付けません。必要に応じて、`NO_COLOR=1`で色を無効化し、`FORCE_COLOR=1`で色を強制できます。

引数を付けずに`node export.js`を実行するか、`--help`を指定すると簡易ヘルプを表示します。

```powershell
node export.js --help
```

`export.yaml`からディレクトリ自体を外した場合、そのディレクトリは同期対象ではなくなるため、以前書き出したファイルは自動削除されません。必要に応じて手動で整理してください。

Windowsの`Desktop.ini`、macOSの`.DS_Store`、Windowsの`Thumbs.db`など、公開用設定に意味のないOS生成メタデータはエクスポート対象から除外します。通常は除外した件数とファイル種別を表示し、`--verbose`を指定した場合だけ個別のパスを列挙します。更新されたファイル名も表示し、変更のないファイルは件数だけ表示します。

スキップされたパスを確認する場合は、次のように`--verbose`を指定します。

```powershell
npm run check:export -- --verbose
npm run build -- --verbose
```
