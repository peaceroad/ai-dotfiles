# Codexの新規チャットでモデル設定が反映されない問題

Codexアプリの新規チャットでモデルや推論レベルを変更しても、すぐ元の値へ戻ることがあります。プロジェクトの`.codex/config.toml`に`model`または`model_reasoning_effort`が定義されている場合は、設定レイヤーの優先順位を確認します。

## 原因

Codexは複数の`config.toml`を重ねて読み込みます。[OpenAI公式ドキュメント](https://learn.chatgpt.com/ja-JP/docs/config-file/config-basic)の優先順位では、プロジェクト設定がユーザー設定より上位です。また、プロジェクトルートから作業ディレクトリまでに複数の`.codex/config.toml`がある場合は、作業ディレクトリに近いファイルが優先されます。

| 優先度 | 設定 | ファイル |
| --- | --- | --- |
| 高 | プロジェクト設定 | `<repo>/.codex/config.toml` |
| 低 | ユーザー設定 | `~/.codex/config.toml` |

モデル関連の同じキーが両方のファイルにあると、プロジェクト設定がユーザー設定を上書きします。新規チャットの画面で別の値を選んでも、Codexの有効値はプロジェクト設定のままなので、画面上の選択もその値へ戻ります。設定の優先順位自体は仕様どおりですが、上書きされる理由が画面に示されない点は[openai/codex#36163](https://github.com/openai/codex/issues/36163)で報告されています。

## 配置の使い分け

プロジェクトの既定モデルを固定する場合は、`<repo>/.codex/config.toml`にモデル関連のキーを置きます。新規チャットごとに画面から選択したい場合は、プロジェクト設定にそのキーを置かず、`~/.codex/config.toml`のユーザー設定または画面上の選択を使います。

このリポジトリで管理する`.codex/`と`.agents/`は、ホームディレクトリにある設定の公開用コピーです。プロジェクト設定として適用されないよう、次のように`home/`配下へ保存します。

```text
<repo>/
└── home/
    ├── .agents/
    └── .codex/
        └── config.toml
```

Codexの作業ディレクトリにはリポジトリルートを使用します。`home/`自体を作業ディレクトリにすると、`home/.codex/config.toml`がプロジェクト設定として検出される可能性があります。

## 一時的に画面から選択する

プロジェクト設定を残したまま挙動を確認する場合は、モデル関連のキーだけを一時的にコメントアウトします。

```toml
# model = "gpt-6-astra"
# model_reasoning_effort = "medium"
```

確認後にプロジェクトの既定値が必要なら、コメントを外します。確認した環境では、タスク開始後にモデルや推論レベルを変更する方法も利用できました。
