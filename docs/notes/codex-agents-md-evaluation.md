# グローバルAGENTS.mdの評価方針

グローバル指示を追加・削除した際に、必要な動作を保てるかと、不要な手順を増やさないかを確認するため、[小さな評価セット](../../evals/codex-agents/README.md)を用意しました。[現行指示の設計理由](codex-agents-md-instruction-rationale.md)を補うものです。2026年9月6日時点ではケースと試行準備を整備した段階で、モデルの行動比較は未実行です。

## 最初に確認する範囲

| 観点 | ケース | 確認したい境界 |
| --- | --- | --- |
| 待機 | 独立作業あり、版の一致が必要、作業なし、継続監視 | 進められる作業は進め、依存関係を越えず、待つべき場面で待つ |
| 完全読み込み | 短い指示、内側の切詰め、外側の切詰め | 全文取得を保証しつつ、短い完全な取得を不要に分割・再読しない |
| LF | CRLF入力の編集と新規作成 | 保存後の実バイトがLFで、変更対象外を巻き込まない |
| 応答品質 | 不十分な比較証拠、単純な計算、明示された要約 | 根拠と不確実性を残し、不要な反復は避け、利用者の指定には従う |
| 環境への適合 | Edgeの明示指定、Windowsファイルリンク | Chrome優先の例外と、実在するローカルファイル参照を扱える |

全条項の網羅から始めず、今回の変更で気になった境界を中心に13ケースとしました。Chromeの既定選択や削除ツールの選択などは、今回のケースでは評価していません。実際の失敗や迷いが生じたときに、その状況と正常に動く対照ケースを追加します。

## 比較の条件

旧版は`c09fde5f`、現行版は`a99578df`の`home/.codex/AGENTS.md`を使用します。完全なコミットID、サイズ、SHA-256は[manifest](../../evals/codex-agents/manifest.json)に固定しています。モデルはAstraにそろえ、推論設定、ツール、権限、上位指示、入力、予算も記録して比較します。

必要なら、グローバル指示を外した`no-global`条件も準備できます。ただしCodexの上位指示やランタイムの機能は残ります。差が出なかった場合、グローバル指示が不要だと即断せず、上位指示の重複、ケースの検出力、偶然の成功を分けて考えます。

公開ケースは改訂中に参照する開発用です。未知の課題への一般化を示す保留評価ではありません。改訂を重ねて同じケースに合わせ込み始めた場合は、次の比較前に別の実例を追加し、採点条件を固定します。

## 結果をどう使うか

準備スクリプトの検査は、ケースの対応や入力生成、比較対象の固定を確かめるものです。モデルの判断は机上試行で、実際の読取・保存・ブラウザー操作はCodexでの試行で確認します。待機の4ケースは現状すべて机上試行であり、イベント配送や監視解除の動作保証には使えません。

採用判断では、重要な失敗の有無、維持すべき動作、不要な呼出しや確認の増減を別々に見ます。短い出力や少ないツール数だけを目標にはしません。旧版のLF検査のように意図的に外した手順は、手順の一致率ではなく成果物の正しさと実行コストで比較します。

最初は毎回の全件実行やCIへの組み込みを必須にせず、AGENTS.mdの変更箇所に関係するケースから実施します。今回なら、完全読み込みの3件とLFの1件を実環境で比較し、待機の4件を机上確認する順序が適しています。少数試行で結果が割れた場合は、失敗した条件を固定して再試行し、原因が指示・環境・取得漏れのどこにあるかを確認します。
