# Codexマーケットプレイス更新用の一時フォルダーを清掃する

利用手順は[`agent codex marketplace-staging`](../agent-codex.md#manage-marketplace-stagingmjs)を参照してください。

## 公開されている問題報告

[openai/codex Discussion #42049](https://github.com/openai/codex/discussions/42049)では、macOSのCodex Desktopで内蔵プラグインの更新用フォルダー`~/.codex/.tmp/bundled-marketplaces/openai-bundled.staging-*`が残り、323個で約31GiBを占有したと報告されています。投稿者は、並行コピーの終了前に失敗時の削除が始まることなどを原因として挙げています。これは投稿者による調査報告で、Windowsでも同じ原因が確認されたという意味ではありません。

同じ命名の古いフォルダーが見つかっても、残存原因や継続的な再発までは断定できません。清掃コマンドは残った一時コピーを除去するためのもので、本体の不具合修正や再発防止を行うものではありません。

## 清掃コマンドの対象と判断

`agent codex marketplace-staging status`は、UUID形式の名前と配下のメタデータを検査します。作成・更新から24時間以上経過した実ディレクトリだけを削除候補にします。この24時間は本ツールの保守的な選別条件であり、Codexの公式な有効期限ではありません。日時だけで未使用と断定せず、`clean`ではクライアントの終了、ロックの不在、確認前後の状態の一致も検査します。

削除は一覧表示と対話確認を経て、検査したファイルと空になったディレクトリを順に消します。親の`bundled-marketplaces`、正規の`openai-bundled`、`.codex/plugins`全体は対象にしません。`.remote-plugin-install-staging`や`plugin-backup-*`も、名前が一時ファイルらしく見えるだけでは同じ扱いにせず、初版の対象外としています。

シンボリックリンク、ジャンクション、ハードリンク、未知のファイル種別、読み取りエラーがある候補は除外します。対象や祖先を操作中に変更する外部処理との競合はサポートしません。清掃用ロックはこのコマンド同士の同時実行を防ぐもので、Codex本体を停止させたり更新をロックしたりする機能ではありません。

## 実装と検証方法

一時的なテスト用フォルダーで、正規フォルダーの保持、古い候補の削除、新しいファイル・リンク・ロックの除外、確認後の変更やクライアント再起動による停止、途中失敗の報告を検証します。`npm run check:agent-dev`で、共通コマンドとWindowsインストーラーを含むテストを実行できます。

プロセス検出の成功・起動中判定・取得失敗はテスト用の応答で検証します。実際の清掃はCodex終了後の通常ユーザーの外部ターミナルから実行してください。プロセス一覧を取得できない場合は、クライアントの終了を確認できないため清掃を拒否します。

`status`では容量と日時だけを集計し、削除用の全項目一覧を保持しません。清掃時は一覧を1回保持し、再検査の際に各項目のメタデータを直接比較します。ツリー全体のJSON文字列化と削除時の配列コピーを省き、削除前の全候補検査・候補ごとの直前検査・各操作前のリンク確認は維持しています。

同サイズで更新日時を戻したファイルの変更や、全候補検査後に変更された候補を検出するテストも含めています。
