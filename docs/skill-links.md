# 開発中のスキルをユーザースコープへリンクする

> **位置付け：** これは、自分が管理する複数のリポジトリにある開発中のスキルを、コピーせず`~/.agents/skills/`から利用するためのローカル規約です。Agent SkillsやAgent Pluginsの仕様、第三者向けの配布・インストール方式ではありません。

スキルの正本をリポジトリに置いたまま、ユーザースコープのシンボリックリンクから参照すると、別のリポジトリで作業するときも同じスキルを利用できます。正本の変更がリンク経由で反映されるため、ホームディレクトリと開発リポジトリの間でファイルを複製・同期する必要はありません。

[OpenAI公式ドキュメント](https://learn.chatgpt.com/docs/build-skills)では、`$HOME/.agents/skills`をユーザースコープの読込先として案内し、シンボリックリンクされたスキルディレクトリも探索対象としています。

この方式は、自分が内容を確認して管理しているリポジトリの開発用途に限定します。第三者へ安定版を配布する場合は、Agent Pluginなどの配布単位を使います。インストール済みプラグインのキャッシュをリンク先の正本にはしません。

主な利用者は、スキルやプラグインを複数のリポジトリで開発する人です。ただし、対象はプラグイン内のスキルに限りません。リポジトリが正本を所有するスタンドアロンのスキルにも同じ方法を使えます。

## プラグイン内のスキルを開発する

プラグイン内のスキルを反復して編集する場合は、各スキルのディレクトリを`~/.agents/skills/`から直接参照すると、プラグインを変更のたびにMarketplaceから再インストールせずに確認できます。この経路は、スキルの指示、参照、スクリプトなどを日常的に開発する用途に向いています。

Marketplaceの登録と、そこからのプラグインのインストールは別の操作です。Marketplaceを登録しただけでは、その中のスキルがユーザースコープのリンクと重複して読み込まれる状態にはなりません。一方、直接リンクと、同じ`name`のスキルを含むインストール済みプラグインを併用すると、正本が同じソースリポジトリでも、Codexから見た発見経路と有効な版が重複し得ます。同名スキルの優先関係には依存せず、同じ環境では一方だけを有効にします。

用途ごとの基本的な切り替えは次のとおりです。

- 日常のスキル開発では、同名スキルを含むプラグインをインストールせず、直接リンク、ソースリポジトリの検証、新しいCodexタスクでの確認を使う。
- プラグイン全体の統合確認では、対象の直接リンクをリンク本体だけ明示的に外すか、同じリンクを持たない別の利用環境を使ってから、Marketplace経由でプラグインをインストールする。
- 直接リンクへ戻す場合は、同名プラグインのインストール状態を解除してからリンクを復元し、新しいCodexタスクで発見元を確認する。

直接リンク経由の確認は、プラグインの`plugin.json`、MCPサーバー、クライアント固有拡張、Marketplace、インストール、キャッシュ更新までを通した証拠にはなりません。配布前には、リンクを使う日常開発とは分けて、必要なプラグイン統合確認を行います。

## 構成

`~/.agents/ai-dotfiles/skill-links.json`が、作成するリンクと参照先の期待状態を宣言します。`~/.agents/ai-dotfiles/runtime/manage-skill-links.mjs`が宣言を検証し、ローカル環境の状態を確認または同期します。

```text
~/.agents/ai-dotfiles/skill-links.json
  └─ 宣言: ~/.agents/skills/<skill-name>
               → 開発リポジトリ内のskills/<skill-name>/（編集する正本）
```

マニフェストの正本はホーム側にあり、開発用PCで利用する複数リポジトリのリンクをまとめたローカル設定です。新しいスキルは、以下のコマンドから登録するか、このJSONを直接編集して追加します。管理スクリプトを変更する必要はありません。

管理スクリプトの正本は`tools/agent/manage-skill-links.mjs`です。`agent`のインストーラーがホーム側の`runtime/`へ実行用コピーを配置し、エクスポートでは書き戻しません。リポジトリ側から単体実行した場合も、既定ではホーム側のマニフェストを読みます。別のマニフェストを明示する場合は環境変数`AGENT_DEV_SKILL_LINKS`を使います。インストーラーはマニフェストを生成・上書きしません。

`npm run build`でこのdotfilesリポジトリの`home/.agents/ai-dotfiles/skill-links.json`へ書き出す際は、参照先がこのリポジトリ内にある宣言だけを選びます。他の開発リポジトリの名前や配置は公開用コピーへ含めません。このため、ホーム側では複数リポジトリを一括管理しながら、公開側のマニフェストをこのリポジトリが正本を持つスキルだけに限定できます。

## コマンドから登録・変更・解除する

`agent`のインストール後、次のコマンドで説明付きメニューを開きます。`development.json`は不要です。入出力をリダイレクトした場合はヘルプだけを表示します。

```powershell
agent dev skill link
```

正式表記は`link`です。以前の`agent dev skill links`も別名として同じ操作を実行できます。

数字・表示された短縮キー・操作名を入力してEnterで確定し、`q`で終了します。名前やパスの入力でEnterだけを押すと、その操作を取り消します。変更操作は対象を表示して`y`で確認し、操作ごとに保存します。単体スクリプトにも同じメニューと操作があります。

操作を直接指定することもできます。次は、自分で用意した開発元を登録する例です。

```powershell
agent dev skill link add my-skill '~/repos/my-project/skills/my-skill'
agent dev skill link status
agent dev skill link sync
agent dev skill link check
```

初回の`add`でJSONを作成します。既存設定があれば登録を追加しますが、同名の登録や、リンク作成先に既存パスがある場合は拒否します。登録だけではリンクを作らず、`sync`で不足するリンクを作成します。参照元はホーム配下のローカルディレクトリに限定し、登録名と同名のディレクトリに`SKILL.md`があることを確認します。絶対パスで指定した場合も、設定には`~/`形式で保存します。Gitで取得したリポジトリも使えますが、取得・Git更新・コードの信頼性確認は別に行います。

```powershell
agent dev skill link update my-skill '~/repos/another-project/skills/my-skill'
agent dev skill link remove my-skill
```

`update`は、登録を変更し、既存リンクが変更前の登録先と一致する場合だけ張り替えます。リンクがなければ設定だけを変更します。`remove`は、登録と、その登録先に一致する既存リンクを解除します。どちらも参照元のディレクトリやスキル本体を削除・更新しません。通常フォルダーや別の場所を指すリンクがある場合は、設定も変更せず停止します。最後の登録を解除した後は空の設定を残し、正常な状態として扱います。

非対話で登録・変更・解除する場合は、対象を確認したうえで末尾に`--yes`を指定します。これは確認への同意であり、安全検査を省略する指定ではありません。既存の`agent dev skill status`、`check`、`sync`も引き続き使えます。

変更中は、ほかのリンク管理処理やJSONの手動編集を止めてください。同じ設定への書き込みは隣接する`.lock`ファイルで排他し、確認後の設定・リンクの変化も検査します。通常の保存失敗ではリンクを元に戻しますが、強制終了や外部からの同時変更まで自動復旧するものではありません。中断後にロックが残った場合は、実行中の処理がないことと設定・リンクの状態を確認してから、ロックだけを取り除きます。

## マニフェストを直接編集する

新しいリンクを追加するときは、`skills`にスキル名と正本のパスを追加します。次は構造を示す例であり、そのまま使う設定ではありません。

```json
{
  "schemaVersion": 1,
  "linkRoot": "~/.agents/skills",
  "skills": {
    "my-skill": "~/git/example/tool-project/plugins/tool-plugin/skills/my-skill"
  }
}
```

マニフェストには次の制約があります。

- `linkRoot`は`~/.agents/skills`とする。
- 参照先は、ユーザー名を含む絶対パスではなく`~/`から始める。
- スキル名と参照先ディレクトリの名前を一致させる。
- `..`を含むパス、重複した参照先、`linkRoot`自身またはその配下を参照先にしない。
- リンク先には`SKILL.md`をファイルとして置く。

## ホームディレクトリから使う

`~/.agents/scripts`を`Path`へ追加して`agent`コマンドを有効にしている場合は、通常は次の短い入口を使います。

```powershell
agent dev skill check
agent dev skill sync
```

`agent dev`の設定とほかの開発対象との境界は、[`agent dev`でローカル開発を管理する](agent-development.md)を参照してください。以下のNode.jsコマンドは、リンク管理スクリプトを直接呼ぶ場合や問題を切り分ける場合に使えます。

マニフェストを変更したら、最初に構造だけを検証します。この段階では、参照先やリンクが存在することを要求しません。

```powershell
node ~/.agents/ai-dotfiles/runtime/manage-skill-links.mjs validate
```

次に、宣言したすべてのリンクについて現在の状態を表示します。`status`は不整合があっても終了コードを失敗にしないため、状況の確認に使えます。

```powershell
node ~/.agents/ai-dotfiles/runtime/manage-skill-links.mjs status
```

参照先と`SKILL.md`を確認したうえで、存在しないリンクを作成します。既存の通常ファイル、通常ディレクトリ、異なる参照先を指すリンクは置き換えません。

```powershell
node ~/.agents/ai-dotfiles/runtime/manage-skill-links.mjs sync
```

最後に、すべての宣言が現在の環境で成立していることを終了コードも含めて確認します。

```powershell
node ~/.agents/ai-dotfiles/runtime/manage-skill-links.mjs check
```

## このリポジトリから使う

このリポジトリのルートからも次のコマンドを使えます。対象はホーム側の設定で、事前のエクスポートは不要です。

```powershell
npm run skill-links:status
npm run skill-links:check
npm run skill-links:sync
```

`npm run check:skill-links`は、一時環境での管理スクリプトのテストと、公開用マニフェストの構造検証を行います。通常の`npm run check`にも含めますが、利用者固有のチェックアウトやシンボリックリンクの存在は要求しません。上記の`skill-links:status`、`skill-links:check`、`skill-links:sync`はホーム側のマニフェストを使います。ローカルリンクまで検証するときだけ`npm run skill-links:check`を明示的に実行します。

## 状態表示を読む

管理スクリプトは、宣言ごとに次の状態を表示します。

| 状態 | 意味 |
| --- | --- |
| `ok` | リンク、参照先、`SKILL.md`が期待どおりに存在する |
| `missing` | 宣言したリンクが存在しない |
| `not-link` | リンクを作成する場所に通常ファイルまたは通常ディレクトリがある |
| `wrong-target` | シンボリックリンクが別の場所を指している |
| `target-missing` | 宣言した参照先ディレクトリが存在しない |
| `missing-skill` | 参照先にファイルとして認識できる`SKILL.md`がない |

`sync`が自動処理するのは`missing`だけです。それ以外は、既存データや別の開発環境を誤って変更しないよう、既存パスを置き換えずに差異を報告し、失敗扱いにします。通常ディレクトリからリンクへ移行するときは、正本との差分を確認してから既存ディレクトリを明示的に整理します。

Windowsでは、シンボリックリンクの作成に開発者モードまたは適切な権限が必要になる場合があります。作成できない場合も、管理スクリプトは通常ディレクトリへのコピーへ切り替えません。

JSONを直接編集して宣言だけを削除しても、`sync`は既存リンクを削除しません。登録と一致するリンクも解除する場合は、宣言を手動で削除する前に`agent dev skill link remove <name>`を使います。

## スキルやAGENTS.mdにしない理由

この管理処理は、明示されたJSONを決定的に検証・同期するローカルツールです。モデルが状況を解釈して手順を選ぶ必要がないため、独立したAgent Skillにはしません。プラグインを作成・検証・配布するスキルとも責務を分けます。

詳しい使い方をグローバルな`AGENTS.md`へ複製すると、リンク管理と無関係なタスクにも指示が常時読み込まれます。通常はこの文書と管理スクリプトを正本にします。特定のリポジトリでリンク管理を必須にする場合だけ、そのリポジトリの`AGENTS.md`に、マニフェストとこの文書を参照する短い規則を置きます。

## `init`を設けない理由

最初の`add`で必要な設定を作成するため、空のひな形だけを生成する`init`は設けません。設定がない場合、`status`は登録方法を案内し、`check`、`validate`、`sync`は未設定として失敗します。いずれも未設定のJSONを自動作成しません。

登録先は利用者が明示的に選びます。リポジトリの自動走査や、Marketplaceから導入済みのスキルの自動登録は行いません。JSONを直接用意する方式も残し、その場合は`validate`、`sync`、`check`の順で確認します。
