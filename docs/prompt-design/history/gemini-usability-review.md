# Geminiスキルの使いやすさと入口の評価

2026年11月15日、`gemini-instruction-design`を評価し、入口の整理版を採用した。この評価では`prompt-design`と`agent-workflow-design`、Gemini側の8参照、description、UIメタデータは変更していない。

評価時の未公開ドラフトには一時的に`0.4.1`を付けたが、公開前の一連の更新として配布版は`0.4.0`へ統一した。以下の語数・ハッシュ・判定と評価JSONの当時の版表示は評価時点の記録である。その後の[公式プロンプト指針の再確認](gemini-4-prompt-audit.md)による変更とは区別する。

## 判断と変更

現行版に、今回の代表依頼を処理できない重大な不具合は見つからなかった。一方、入口には共通スキルが既に所有する作業範囲・報告・指示品質の説明や、通常の実行には不要な保守担当向けの注意が重なっていた。これらを削り、入口を対象範囲、共通スキル、用途別参照、成果物と実行の境界に整理した。

`prompt-design`は一度読み、必要な参照選択は同スキルに従う。実行制御の設計では`agent-workflow-design`の本文と必要な参照を読む、と明記した。兄弟ディレクトリまたは利用可能なカタログから解決し、利用者が共通スキル名まで指定する必要はない。Antigravityを使うだけでワークフロー設計を必須にはしない。

入口は空白区切りの英語語数で743語から519語へ、約30%減った。必読の`prompt-design`本文1,308語を含めると2,051語から1,827語で約11%減となる。これは配布ソースの読み込み量の比較であり、実際のトークン、速度、費用の測定ではない。参照8本は依頼のまとまりとして妥当で、常時読む必要もないため、数を減らす目的の統合は行わなかった。

採用理由は、事前に定めた「共通手法や保守指示の重複を減らす」という構造上の改善と、代表依頼で重要な条件を失わなかったこと。出力品質が一般的に向上した、または短い版が常に優れるという結論ではない。

## 評価方法

[評価契約](../../../evals/agent-design-tools/prompt-design/gemini-usability/contract.json)を先に固定し、現在のソースと候補を別コピーへ凍結した。[入口の変更前](../../../evals/agent-design-tools/prompt-design/gemini-usability/versions/before.txt)・[候補](../../../evals/agent-design-tools/prompt-design/gemini-usability/versions/candidate.txt)と[協働スキルを含むソースハッシュ](../../../evals/agent-design-tools/prompt-design/gemini-usability/source-versions.json)を残した。各試行は作業履歴を渡さない新しいエージェントで実施し、設定はホストから継承した。具体的なバックエンド版・推論設定・課金額は取得していない。

実行担当には自然な依頼、使用スキルの場所、固定資料を使うこと、実サービス操作を行わないことを渡した。期待回答と採点基準は渡していない。ただし、スキルを明示指定し、試行であることが分かる操作制限も与えている。共有ファイルシステム上のコピーは厳密なアクセス隔離ではない。

主担当は実際の成果物を、要件保持、利用可能な出力、正しい制御層、根拠と実行の区別で判定した。タイムアウト後の新規キー再送、Omniの未対応入力の保証、成果物のない説明などを不適合とする校正例を契約に含めた。語数や見栄えだけで採点せず、好みの比較や統計的優越性の判定は行っていない。読み込んだ参照一覧は担当者の自己報告であり、独立した計測ログではない。

## 結果

上限18回のうち16回のワーカー実行を完了し、すべての成果物を確認した。候補は1版で、結果に合わせた追加改稿はしていない。[判定と成果物一覧](../../../evals/agent-design-tools/prompt-design/gemini-usability/results.json)から回答本文へたどれる。

- **5種類の同条件比較、計10実行：** 短いプロンプト、Apps抽出スキル、状態保持と一度限りの外部登録、Hydrogen API指示、Omni延長を比較した。両版とも要求された成果物を作り、今回の必須条件を満たした。短い依頼では追加参照なし、実行制御の依頼では両版ともワークフロー側を利用した。
- **カタログ判定、1実行：** 3スキルの名前・descriptionだけから12依頼を選別した。主担当の点検では、設計依頼、通常作業、生成そのもの、一般質問の境界は適切だった。状態管理だけの依頼は`agent-workflow-design`が入口になり、Geminiという語だけで専用スキルへ寄せていない。descriptionは両版で同じなので、改稿による選択改善の証拠ではない。
- **生成物の下流試行、2実行：** 各版が生成したApps抽出スキルを別のホスト文脈で実行した。両方とも、本文中の不正な指示を採用せず、利用者のキー名変更を反映し、期限未定を`null`として有効なJSONを返した。未確定事項を空配列にする回答と説明を添える回答は、いずれも許容した。
- **選択後の確認、2実行：** 調整に使っていないCLIとGems／Opal移行の依頼で確認した。常時規約と任意スキル、未確認の配置設定、自動変換と再設計、資料・機能の損失を区別できた。
- **複合依頼の追加確認、1実行：** Appsと画像の参照を組み合わせ、`gemini-3-pro-image`を対象外にせず、商品形状・日本語ラベルの保持と夕景への変更を両立する指示を作れた。以前にも扱った依頼系列なので、独立した未知の課題としては数えない。

下流試行は生成した指示の働きを確かめる補助証拠だが、実行したのはGemini Appsではない。カタログ判定もインストール済みクライアントの自動発火ではない。実際のApps取込み、Geminiの回答品質、動画・画像生成、外部登録の障害復旧は今回の検証範囲外である。

## 適用と保守

採用前に候補のスキルvalidatorとportable plugin validatorを通し、変更前ソースとの一致を確認してから入口を適用した。共通スキルや参照には介入していない。適用後の`npm run check:plugins`は26件すべて成功し、単独配置時の参照到達性も確認した。採用版と試行版のハッシュ一致、共通2スキルとGemini参照の不変、文書リンク、LFも最終確認した。

利用者環境への導入や公開は行っていない。今後は短さだけを理由にさらに削らず、依存解決の失敗、不要な参照、対象環境で使えない成果物などの観測があれば、その判断箇所を見直す。実機の自動選択や媒体品質を保証する場合は、それを測る別の試験が必要になる。
