# Gemini 4のプロンプト指針と現行スキルの再評価

2026年11月15日、Gemini 4 Carbon・Argon・Hydrogenと、Nano Banana・Omniの公式資料を再確認した。現行の責務分担は維持し、APIの回答予算とOmni延長時の入力条件を補った。共通の`prompt-design`と`agent-workflow-design`は変更していない。未公開の全面改稿と追加調整を一つのリリースとして扱い、プラグイン版は`0.4.0`へ統一した。

## 公式資料と設計の分担

前回本文を確認できなかった[Carbon専用開発ガイド](https://aistudio.google.com/learn/gemini-4-carbon-developer-guide)を今回は本文まで読み、[Argon専用開発ガイド](https://aistudio.google.com/learn/gemini-4-argon-developer-guide)とも照合した。長い作業では、明確な目標、現実の検証結果、適切な媒体資料、作業から得た知見の再利用が中心になっている。

これらのうち、成果・制約・証拠・完了条件は既存の`prompt-design`が扱う。待機、委任、中断復帰、継続、知見による手順改善を設計する場合は、`agent-workflow-design`の既存の判断と参照を利用できる。Carbonを調整役にする公式例を、すべての依頼で複数エージェントを使う規則にはしない。具体的な構成は対象ランタイムと依頼の要件で決める。この対応関係から、Gemini用の共通手法をもう一組増やす必要はないと判断した。

[Hydrogenガイド](https://aistudio.google.com/docs/whats-new-gemini-4-hydrogen)では、思考レベル、回答予算、ネイティブなツール宣言、API別の状態保持を再確認した。後二者は既存のAPI参照が扱えていたが、`max_output_tokens`が思考と最終回答の合計を制限することは明記されていなかった。ここは短いJSON抽出でも設定判断を変えるため補った。

[Nano Bananaガイド](https://aistudio.google.com/docs/image-generation#prompt-guide)と[DeepMindの画像プロンプトガイド](https://deepmind.google/models/gemini-image/prompt-guide/)については、目的、構図、参照の役割、確定した文字列、変更と保持の条件、反復編集を照合した。現行の画像参照で扱える。公式の詳細化・段階化の例を、短い依頼にも強制するテンプレートにはしない。DeepMind側への出典説明は、実際に掲載された主題・場面・構図・画風・反復編集の範囲へ修正した。

[Omniガイド](https://aistudio.google.com/docs/omni#prompt-guide)は、新規生成、編集、延長で必要な指示の違いを確認した。固定ショット、短い編集指示、時間指定、音声の区別は既存参照にあった。一方、延長では末尾10秒だけが文脈になること、延長用の参照動画は受け付けないこと、system instructionや独立したnegative-prompt欄がないことを補った。これらはプロンプトの内容と入力の組み立てに直接影響する。

## Gemini 3向け資料を残さない範囲

現行スキルにGemini 3汎用モデルの互換ガイドはない。今回の再確認でも、世代が混在する公式共通ページのGemini 3向け節を、Gemini 4の固有助言の根拠には採用していない。API参照の出典はGemini 4の各モデル資料へ寄せ、旧世代の説明へ誘導する共通ガイドのリンクを外した。

入口と媒体入力参照に残っていた「長い資料の後に問いを置く」という一律の配置指示も外した。これは配置方法自体を禁止する変更ではなく、Gemini 4固有の必須手順として維持する根拠が不足しているためである。資料と指示の分離、各入力の役割、依頼に合う構成は共通手法と媒体入力参照で扱う。

入口と画像参照から、Gemini 3を対象外と繰り返す保守上の説明も削った。Nano Bananaの正式な画像モデルIDはそのまま保持する。過去の評価記録は当時の条件を示す証拠として残し、現行設計の必読資料にはしていない。

## 固定した課題による確認

[評価契約](../../../evals/agent-design-tools/prompt-design/gemini-4-prompt-audit/contract.json)、[依頼](../../../evals/agent-design-tools/prompt-design/gemini-4-prompt-audit/requests.json)、変更前後の束を固定し、3課題を各版1回、計6回実行した。対象はホストの新しいエージェント文脈で、モデル・推論設定は継承し、上書きしていない。スキルの使用先を明示し、期待解や判定基準は渡さなかった。共有ファイルシステムの厳密なアクセス隔離や、実クライアントでの自動発火を測ったものではない。

主担当が実際の回答を契約の条件で判定した。詳細と回答本文は[結果記録](../../../evals/agent-design-tools/prompt-design/gemini-4-prompt-audit/results.json)にある。

- **Carbonの長時間作業指示：** 両版とも、公開APIと検索条件を保ち、修正前後の計測、実画面の確認、保存済み状態と現在状態の照合を含む指示を作れた。共通2スキルと必要なワークフロー参照を利用し、独自のエージェント構成や毎回の承認を追加しなかった。
- **Hydrogenの短いJSON抽出：** 両版とも指示文と設定助言を分け、欠損値を`null`とする形を保った。変更前は思考が上限に算入されるかを未確定とした。変更後は合計上限を明示し、既存の費用上限を維持した低い思考レベルの試験を提案できた。予算増額やモデル変更を勝手に前提にしていない。
- **Omniの再登場シーン：** 両版とも14秒動画を6秒延長するプロンプトを作れた。変更前は参照動画と入力欄の対応を未確認とした。変更後は冒頭だけの登場が末尾10秒に含まれないことを説明し、文章または被写体の参照画像で補う形にできた。延長の時間原点、固定カメラ、音楽・セリフなしも保った。

読み込み一覧は担当者の自己報告であり、独立した計測ではない。両版のOmni試行では動画参照に加えて一般API参照も読んだが、修正版はOmni固有の未対応フィールドを優先していた。一般API参照が必須という結論や、参照読み込みが最小化されたという主張にはしない。

前回の[使いやすさ評価](gemini-usability-review.md)の採用版と、今回の変更前のスキル25ファイルはハッシュが一致した。短い文章指示、Appsと画像の複合依頼、生成物の下流応答は保存済みの成果物を読み直した。ただし、前回の16実行を今回の新規実行として数えていない。

## 採用範囲と限界

採用理由は、公式仕様で解消できる不足を参照へ反映し、3課題で必要な成果物と条件を保持できたこと。Gemini側の変更は入口と4参照に限定した。`SKILL.md`は空白区切り519語から481語へ減ったが、短さを性能向上の証拠にはしていない。参照は引き続き8本で、用途別に読む。

候補へskill validatorとportable plugin validatorを適用し、介在する変更がないことを確認してからソースへ反映した。凍結版、変更ファイルの内容、共通スキルのハッシュは[版記録](../../../evals/agent-design-tools/prompt-design/gemini-4-prompt-audit/source-versions.json)に保持している。評価時のドラフト版`0.4.1`は過去の証拠として書き換えず、配布manifestと現行案内を`0.4.0`にそろえた。

反映後の`npm run check:plugins`は26件すべて成功した。配布内と単独配置時の参照到達性、現行ソースと凍結候補の一致、保存した版のハッシュ、JSON、文書リンク、LF、差分も確認した。現在の配布スキル内に残る`gemini-3`は、Nano Bananaの正式な画像モデルIDだけである。

今回確認したのは公式資料との整合と設計スキルが作る指示である。Gemini実機での応答、画像・動画の生成、Appsへの取込み、長時間処理の復旧は実行していない。トークン、費用、速度も未測定であり、一般的な最適性や実サービスの品質向上は主張しない。

## 追加の範囲整理：Gems／Opalの専用参照を廃止

同日、利用者の運用をGemini 4とApps Skillsの設計へ絞る方針に合わせ、`gems-migration.md`、入口の移行用途・読み込み条件、Apps参照からの誘導を削除した。プラグインREADMEも現在の7参照へ合わせた。共通2スキルとUIメタデータは変更せず、版は未公開の`0.4.0`を維持する。

旧参照は、移行に伴う資料や機能の損失を扱うために残していた。今回は配布スキルの保守範囲を狭める判断であり、全アカウントの移行完了を認定するものではない。具体的な移行依頼には、その時点の公式資料を確認する既存の方針を使う。

過去の移行試行が使った[参照本文](../../../evals/agent-design-tools/prompt-design/gemini-usability/versions/gems-migration.txt)は、記録済みのハッシュと一致する版を評価資料として保全した。過去の回答・判定・版情報は書き換えていない。この範囲整理は上記6回の比較後の変更であり、比較結果を新しい発火範囲の実測結果とは扱わない。

整理後もskill validatorと`npm run check:plugins`の26件が成功した。配布スキルとREADMEにGems／Opalの読み込み経路が残っていないこと、7参照への到達性、共通スキルの不変、退役参照のハッシュ一致、文書リンクとLFを確認した。descriptionは旧移行用途だけを外し、既存の設計用途と通常実行の除外を保持している。新しいカタログ発火試行は行っていない。

## 追加監査：Skillsの公式仕様と古い説明の残存

同日、入口と7参照、配布README、現行の案内から旧資料への導線を再点検した。Skillsは提供面ごとに公式本文を確認し、共通するファイル形式と各クライアントの読込み・実行条件を区別した。

- **Apps：** [作成指針](https://support.google.com/gemini/answer/17102773?hl=en)と[管理ヘルプ](https://support.google.com/gemini/answer/17094296?hl=en)を照合した。説明から必要な本文・資料へ進む既存設計は整合していた。添付形式の確認を補い、TypeScriptなどをそのまま同梱できる前提を避けた。DriveファイルとNotebookはダウンロードZIPに含まれないため、外部依存として扱う。ファイル更新については、全体再アップロードと個別更新の説明が併存するため、実操作時のUI確認を残した。
- **Gemini CLI：** [Agent Skills](https://geminicli.com/docs/cli/skills/)と[作成ガイド](https://geminicli.com/docs/cli/creating-skills/)から、メタデータ、`activate_skill`、同意、ディレクトリ構造を確認した。YAMLと本文の構成を明示し、組込みスキルが事前承認済みである点を補った。実行権限は引き続きCLI側の契約に従う。
- **Antigravity：** [Skills](https://antigravity.google/docs/skills)、[Rules](https://antigravity.google/docs/rules)、[探索仕様](https://antigravity.google/docs/customization-discovery/)を照合した。ターンごとの選択、常時制約と手順の分担は維持し、探索対象の階層と大きなRulesの読込み制限を補った。

[Agent Skills仕様](https://agentskills.io/specification)の形式は移植可能な成果物の基準として使う。標準の任意フィールドを各クライアントがすべて同じように解釈するとは扱わない。Apps参照にも、この確認条件を明記した。

動画参照に残っていたVeoの旧API退役日とOmni旧版の切替予定は削除した。現行の[Cloud Veoモデル](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/veo/3-1-generate)を明示指定された場合の確認条件は維持する。Nano Bananaの正式IDに含まれる`gemini-3`と、READMEのスキル改名案内も、それぞれ現行の対象識別と利用者の呼出し更新に必要なため残した。Gems／OpalやGemini 3汎用モデルの設計手順は配布スキルにない。

変更は4参照に限定し、入口、共通2スキル、参照数7本、版`0.4.0`を維持した。これは公式仕様の照合と静的検査による補正であり、新たなモデル比較試行ではない。以前の凍結版・回答・判定は保持し、その比較結果を今回の修正版の実測結果として扱わない。Appsへの取込み、自動選択、各クライアントでの実行は今回も未検証である。

補正後もskill validator、portable plugin validator、`npm run check:plugins`の26件が成功した。7参照への導線、文書リンク、LF、共通スキルの不変、配布スキル内の旧用途・退役日付の除去を確認した。横断検索で見つかった過去の計画・評価・改稿記録は、実行時の導線と区別した。配布スキルとプラグインREADMEに残る旧名・旧モデル名は、上記の改名案内と正式な画像モデルIDだけだった。

## 仕上げ：案内の確認漏れと併用条件の修正

続く確認で、リポジトリルートのREADMEにGems移行を支援するという説明が1文残っていた。これは前回の確認漏れであり、削除した。英語名に日本語が隣接する表記も拾うよう、単語境界に依存しない検索で現行の案内と配布内容を再確認した。過去の計画・評価本文は履歴として保持する。

API参照には、制御ループの実装を理由に`agent-workflow-design`へ誘導する条件が残っていた。これは共通スキルが除外する通常のアプリケーションループまで対象に広げ得るため、委任・待機・復旧・反復作業の制御を設計する場合に絞った。通常のツール呼出しループを実装するだけなら、この併用は不要と明記した。共通スキル自体は変更していない。

プラグインREADMEは、3スキルの選択、具体的な依頼例、Geminiでの併用、対象モデル、導入と更新、背景出典、評価記録の順へ再構成した。Geminiスキルを呼べば必要な共通スキルを読むこと、単独導入時の依存関係を明示した。過去のモデル移行例の表と詳細な内部読込み手順は縮め、既存対象を保持する方針、改名時の更新案内、出典への到達性は維持した。

この仕上げは文書と適用条件の静的レビューであり、新しいモデル試行ではない。入口の厚さと7参照の構成、版`0.4.0`は変更していない。修正後の`npm run check:plugins`は26件すべて成功し、文書リンク、LF、差分、共通スキルの不変も確認した。
