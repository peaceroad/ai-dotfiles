## GPT-5.6参照を残す理由と監査結果

既存のGPT-5.6向け指示を改訂する用途には、専用の入口を残す価値があります。現在も[GPT-5.6公式ガイド](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6)があり、出力の簡潔さや移行時の調整を扱っています。たとえばAPIで`none`を使えるため、Astra移行時の`low`への変更を既存のGPT-5.6環境へ当てはめるべきではありません。

Gitの基点コミット`7c687ab81b7a30e76ac7ee90afc8fce31f5693e3`から旧参照を全文取得し、現行の共通本文・API参照・公式ガイドと照合しました。

| 旧参照の内容 | 復元時の判断 |
| --- | --- |
| OpenAI/Codex全般をGPT-5.6として扱う入口 | GPT-5.6が設計対象で、モデルの挙動や設定が判断に関わる場合に限定 |
| 簡潔な出力、蓄積した指示の整理 | 必要な説明が消える場合や指示が重複する場合の調整として保持。短さだけを改善としない |
| 成果・根拠・権限・完了条件などの共通原則 | 現行の`SKILL.md`に集約。参照ごとの再定義を避ける |
| 外部操作での確認、並列結果の統合、経路を変えない助言 | 既存の許可があっても再確認する、全結果を一律に待つ、状況が変わっても経路を固定すると読める指示は戻さない。共通の権限・依存関係・引き継ぎの規則を使う |
| API・PTC・履歴・キャッシュの詳細 | 共通のAPI参照へ案内し、対象モデルの対応を確認。Astra固有の節の適用範囲も明示 |
| effortの比較 | 実際のGPT-5.4/5.5からの移行時に行う比較と、普通の文言修正を区別 |

[復元した参照](../../plugins/agent-design-tools/skills/prompt-design/references/openai-gpt-5.6-prompt-design.md)は15,066 bytesから3,163 bytesになりました。削減の主因は共通部分の集約です。GPT-5.6向けでもモデル非依存の文言修正なら追加読み込みは不要とし、Astra向け作業の読み込み増加は入口1行の211 bytesに留めています。

## Geminiを同じスキルに残す判断

Geminiの参照は、一般的な指示設計、GemのInstructionsとKnowledge、画像・動画の生成指示の3つです。成果、制約、例、根拠、指示の強さを設計する判断は共通本文と共有し、製品固有の扱いを必要時に読む構成になっています。Googleの[プロンプト設計ガイド](https://ai.google.dev/gemini-api/docs/prompting-strategies)と[Gem作成のヒント](https://support.google.com/gemini/answer/15235603)も照合しました。

| 観点 | 現状の参照構成 | 別スキルにする場合 |
| --- | --- | --- |
| 入口と読み込み | `prompt-design`から対象別に進む。AstraとGeminiの参照を一括では読まない | Gemini専用の入口で製品操作まで直接案内しやすくなる |
| 共通原則の保守 | 指示設計の判断を1か所で更新できる | 共通部分を複製するか、別スキルを追加で読む依存関係が必要 |
| 機能の境界 | 指示文の設計が主目的。APIパラメーターとGemini Appsを区別 | Gemの設定・共有・検証などを一貫して実行する独立用途に向く |
| 確認できた根拠 | 初回R06はGemini・Gem参照を選び、Astra参照を読み込まなかった | 分離後の自動選択・品質・待ち時間の改善は未比較 |

現状は、共通の指示設計を保ちながら対象固有の参照を選べています。Gemの作成・設定・共有・更新まで扱う依頼が増える、または誤った参照選択が繰り返される場合に、独立した用途として分割を再検討します。今回の配置判断は保守上の判断であり、参照の維持が常に高性能だと実証したものではありません。

## 検証と限界

利用者向けの説明として、スキルのREADMEへモデル選択の例を追加しました（現在は[プラグインのREADME](../../plugins/agent-design-tools/README.md#target-model)へ統合）。既定のAstraと既存の利用先の優先関係、実行中モデルへ自動追従しないことを説明しています。同日にGPT-5.6公式ガイドのPrompting best practicesを再確認し、簡潔さ、権限、Pro mode、PTCの助言を専用参照・共通本文・API参照と照合しました。追加修正を要する点は見つからず、指示ファイルは維持しています。

参照の復元時に変更した指示は、`SKILL.md`のGPT-5.6への入口とGPT-5.6参照です。Astra・Gemini・APIの既存参照とスキルのdescriptionは維持しています。入口の条件と本文の適用範囲、設定の出典、相対リンク、文書の意味と読みやすさを静的に確認しました。`quick_validate.py`と`npm run check:plugins`、JSON・ハッシュ・差分・LFの検証も行いました。

GPT-5.6参照復元時の指示・参照・メタデータ10ファイルのハッシュと直前版の復元情報は[model-reference-manifest.json](../../evals/agent-design-tools/prompt-design/model-reference-manifest.json)にあります。利用者向けREADMEはこの指示の版管理に含めず、スキルの必読参照にも加えていません。過去のケース・応答、指示の版と評価結果は維持しています。R05の短いGPT-5.6向け修正とR06のGem向け指示生成は、今回の構成変更前の証拠です。新しい動作試行、GPT-5.6やGemini本体での実行、スキル分離との性能比較は行っていません。

## 出典リンクと表の整理

2026年9月6日、コミット`51c1c8c`を基点に、出典リンクが不要な閲覧を促さないか、表が理解を妨げていないかを確認しました。OpenAIの3参照では公式URLを末尾の「Official sources」へまとめ、Gem参照では末尾と重複していた本文中のURLを外しました。本文には判断に必要な説明と、仕様確認が必要になる条件を残しています。`SKILL.md`の既存の参照条件に、外部リンクは出典であり必読一覧ではないという1文を追加しました。

`SKILL.md`と8つの参照にある表は、APIの呼び出し経路を比べる4行・3列の表と、動画の作業種別に応じた指示を示す5行・2列の表の2つです（行数は見出しを除く）。いずれも短い対応関係を表しており、箇条書きへ変える必要はないと判断しました。利用者向けの共通READMEにある2つの表も、スキルの使い分けと対象モデルの選択に役立つため維持しています。

出典URLとローカル参照先の保持、表の内容、プラグイン構造、差分、LFを静的に確認しました。今回の整理ではモデル・APIの事実を更新しておらず、公式資料の確認日と過去の評価・manifestは維持しています。リンクの移動だけで閲覧が抑制されるとは限らず、閲覧回数・トークン数・下流の実行結果を比較したものではありません。
