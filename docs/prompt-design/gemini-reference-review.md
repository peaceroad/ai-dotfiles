## imagegenとImagenから転用した範囲

Codexの`imagegen`スキルとその`references/prompting.md`は、参照画像の役割、具体的な変更点と保持条件、正確な文字、必要な余白、編集時の一貫性を整理するうえで役立ちました。個々の指定はGeminiの仕様と依頼の裁量に合わせて調整し、構図や画風を任された場合には判断の余地を残しています。Gemini参照を使う際に`imagegen`を読み込む依存関係は追加していません。

Googleの[Imagenプロンプトガイド](https://ai.google.dev/gemini-api/docs/imagen#imagen-prompt-guide)と[Vertex AIの編集ガイド](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/image/edit-images-overview)は、被写体・背景・画風や編集の説明を補う資料です。Imagenの文字数目安やnegative prompt欄、OpenAI固有の品質・忠実度・マスク・透過設定は、Geminiの共通機能として転用していません。

提供状況にも注意が必要でした。[Gemini APIの廃止一覧](https://ai.google.dev/gemini-api/docs/deprecations#imagen-models)では、Imagen 4の対象モデルの終了日は8月17日です。これはGemini APIの記述であり、Vertex AIを含めたImagen全体の終了とは扱いません。再利用する指示にはモデル一覧や料金表を抱え込まず、作業結果に影響する機能だけ、その導入先で確認する形にしました。

動画は[Omni](https://ai.google.dev/gemini-api/docs/omni#gemini-omni-flash-prompt-guide)と[Veo](https://ai.google.dev/gemini-api/docs/veo#veo-prompt-guide)を個別に照合しました。特にOmniの延長は、新しい区間を起点に時刻を指定し、接続のため元動画の末尾フレームが変わる場合があります。プロンプトだけで元動画の完全な保持を約束しないようにしています。

## 2026年9月11日：対象世代とメディア参照の整理

補助スキルの保守対象をGemini 3以降と明記しました。旧世代向けの手順や回避策は採用せず、世代が混在する公式ガイドでも対象モデルに適用できる部分だけを使います。小数版が指定されていないときはGemini 3のプロンプト設計を基準にし、特定のモデルIDやデプロイ先へ勝手に切り替えません。Omni・Veo・Imagenは別のバージョン体系として、それぞれの現行ガイドを使います。

今回の確認では、[Gemini 3.5 Flashの公式ガイド](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5#prompting-best-practices)にもプロンプト設計の節がありました。共通参照へ追加しましたが、同ページのAPI移行手順や特定モデルの設定を、すべてのGemやプロンプトへ必須にはしていません。[最新モデルガイド](https://ai.google.dev/gemini-api/docs/latest-model)は現在の変更を確認する入口であり、設計対象を自動選択する根拠とは区別しています。

メディアは、求める成果物によって参照を選びます。

- **入力の理解：** [メディア入力の参照](../../plugins/agent-design-tools/skills/prompt-gemini-reference/references/gemini-media-input-prompt-design.md)を追加しました。抽出対象、根拠の画像・ページ・時刻、読み取れない箇所の扱い、視覚・音声・推論の区別を整理しています。入力順序は一律に固定せず、単一画像と複数メディアの対応関係で判断します。
- **生成・編集：** 既存の画像・動画参照を維持しました。参照画像の役割、編集時の保持条件、文字、反復、動画の時間と音声は共通する判断が多いため、今回は画像用と動画用のファイルには分割していません。動画の概要ページを選択の入口に加え、能力の判断はOmni・Veoの詳細ガイドへ進む形にしました。
- **両方を使う場合：** メディアを詳しく分析したうえで生成用の指示へ変換する依頼では両参照を読みます。単に生成用の参照画像が付いているだけなら、入力分析の参照まで毎回読みません。

公式資料同士でも適用範囲を分ける必要がありました。[Filesのプロンプトガイド](https://ai.google.dev/gemini-api/docs/files#prompt-guide)にはtemperatureを下げる助言がありますが、Gemini 3.x向けのモデルガイドは既定のサンプリング設定を勧めています。読み取りや根拠の問題を先に調べ、モデル固有の設定はAPI側で確認する方針にしました。また、[動画の概要](https://ai.google.dev/gemini-api/docs/video)の比較表現だけで機能の独占性を判断せず、延長などの更新は[Omniの詳細ガイド](https://ai.google.dev/gemini-api/docs/omni#prompts-for-extending-a-video)を優先します。

AI Studio側の[プロンプト](https://aistudio.google.com/docs/prompting-strategies)、[ファイル](https://aistudio.google.com/docs/files#prompt-guide)、[画像生成](https://aistudio.google.com/docs/image-generation)、[動画生成](https://aistudio.google.com/docs/video)も候補として確認しました。ただし、この環境ではHTTP応答は得られても動的表示の本文を取得できず、本文を確認できた`ai.google.dev`側を今回の根拠にしています。両サイトの全文の同一性やAI Studio側の更新差分を確認した記録ではありません。

続く見直しでは、通常のプロンプト設計を同梱の指針で仕上げることを入口に明記しました。公式確認は、最新の指針を求める依頼、モデル移行、手元の根拠だけでは確定できず結果に影響する仕様に絞ります。確認できない仕様があっても、それに依存しない文章・構図・保持条件の設計まで止めません。画像・動画では、使えるプロンプト本文と、必要な添付物の対応・設定上の注記を分けて渡す方針にしました。重複した世代の注意と確認条件を整理し、出典の確認日は出典欄へ移しています。共通手順をGemini側へ複製したり、GPT-6と同じ挙動・機能を持つと仮定したりする変更ではありません。

`skill-creator`と`prompt-design`の方針に沿って、descriptionは長くせず、対象世代と参照条件を本文に置きました。プラグインの版は`0.3.1`です。スキル検証、`npm run check:plugins`の3パッケージ検証と5テスト、差分の空白検査が成功しました。入力分析だけ、画像編集だけ、動画延長、分析と生成の併用について読み込み条件を机上確認しています。Geminiでの実行や画像・動画の生成による品質確認、インストール済みコピーや共有Marketplaceの更新は行っていません。過去の評価manifestも変更していません。

### 最新ガイドとのずれと使い勝手の再確認

同日、共通スキルと補助スキルの入口、4参照を読み直し、Google公式の現行ガイドと照合しました。確認した範囲では、最新モデル向けの推奨から大きく外れる指示は見当たらず、スキル本文は追加変更していません。

- **文章向け：** [Gemini 3の指針](https://ai.google.dev/gemini-api/docs/prompting-strategies#gemini-3)と[3.5 Flashのプロンプト設計](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5#prompting-best-practices)にある、明確で直接的な指示、必要な説明量の指定、長い資料の後への問いの配置を反映しています。旧モデル向けの複雑な推論誘導を一律に追加しない方針も一致しています。
- **最新モデル固有の注意：** 確認時の[最新モデルページ](https://ai.google.dev/gemini-api/docs/latest-model)はGemini 3.8 Flashを案内しています。複雑なタスクでは検証やツール呼び出しが増える場合があり、日常的なタスクでは推論量を下げる選択肢が示されています。ただし、同モデルでは`minimal`は非対応で、移行手順は`temperature`・`top_p`・`top_k`の削除を案内しています。3.5の設定例をそのまま転用せず、必要な場合に対象モデルとAPIの仕様を確かめる現行方針を維持します。これらの設定をGemの指示文へ書いても、API設定にはなりません。
- **画像・動画向け：** [ネイティブ画像生成ガイド](https://ai.google.dev/gemini-api/docs/image-generation#prompting-guide-and-strategies)の目的・構図・正確な文字・部分的な修正、[Omniのガイド](https://ai.google.dev/gemini-api/docs/omni#gemini-omni-flash-prompt-guide)の連続ショット・簡潔な編集指示・音声・延長時の時間指定を、現行参照で扱えています。テキストモデルの最新番号を画像・動画へ当てはめたり、全メディアに同じ設定を要求したりはしません。

使い勝手は、文章向け指示、画像の照明変更、添付動画の分析、動画延長、GemのKnowledge利用、Geminiを指定しない画像生成の依頼で、選択条件と必要な参照を机上確認しました。共通手順を一度読み、用途に必要な補足だけを選べます。生成指示だけの依頼でメディア生成へ進まないことや、照明変更を元の照明の保持条件で妨げないことも確認しています。通常の設計を毎回の公式資料調査へ広げる必要はありません。

これは公式推奨との整合性と指示文の静的な確認であり、「最新モデルで最良のプロンプトを作れる」と実証した記録ではありません。Geminiでの比較試験、新しいタスクでの自動選択、実際の画像・動画生成は未実施です。AI Studio側の動的な本文を確認できていない制約も残ります。今後の実利用で、長い資料からの抽出、画像の文字と同一性、動画の連続性に問題が出た場合は、モデル・設定・入力を記録して該当箇所を修正します。
