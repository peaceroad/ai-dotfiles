## 3参照の変更と判断

| 参照 | 変更の中心 |
| --- | --- |
| [Gemini共通](../../plugins/agent-design-tools/skills/prompt-design/references/gemini-prompt-design.md) | 対象製品、指示と入力の役割、長い文脈と問いの配置、根拠と推測を整理。必要な説明まで短くしない。内部の推論を逐一表示させる代わりに、利用者に必要な根拠や成果物を指定する |
| [Gems](../../plugins/agent-design-tools/skills/prompt-design/references/gemini-gems-prompt-design.md) | 通常のGemsとLabsのミニアプリを区別。InstructionsとKnowledgeの分担、Driveの更新、Notebookの扱い、共有時の閲覧範囲、引用設定、プレビューと保存を整理する |
| [画像・動画](../../plugins/agent-design-tools/skills/prompt-design/references/gemini-media-generation-prompt-design.md) | 新規生成と既存画像の編集を分け、参照画像の役割、変更点と保持条件、文字、多言語化、連続画像の一貫性を明確にする。動画では生成・編集・延長を区別し、ショット、時間、音声の条件を必要に応じて指定する |

Nano Banana専用資料からは、人物・物体に一貫した名前を付けること、多言語化で文字とデザインの変更範囲を分けること、複数画像と一覧画像を区別することを補いました。現在の事実に依存する図では、利用できる検索・提供資料で確かめた内容を、どの視覚要素へ対応させるかを指定します。架空の描写や画像の見栄えを根拠の代わりにはしません。

詳細な依頼では要件を保持し、自由度のある依頼では、その範囲で創作上の詳細を足せるようにしました。すべての画像へカメラ・材質・照明の項目を強制する設計にはしていません。反復は観測した欠陥に対応させ、満たした要件を不要に作り直さない方針です。

## imagegenとImagenから転用した範囲

Codexの`imagegen`スキルとその`references/prompting.md`は、参照画像の役割、具体的な変更点と保持条件、正確な文字、必要な余白、編集時の一貫性を整理するうえで役立ちました。個々の指定はGeminiの仕様と依頼の裁量に合わせて調整し、構図や画風を任された場合には判断の余地を残しています。Gemini参照を使う際に`imagegen`を読み込む依存関係は追加していません。

Googleの[Imagenプロンプトガイド](https://ai.google.dev/gemini-api/docs/imagen#imagen-prompt-guide)と[Vertex AIの編集ガイド](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/image/edit-images-overview)は、被写体・背景・画風や編集の説明を補う資料です。Imagenの文字数目安やnegative prompt欄、OpenAI固有の品質・忠実度・マスク・透過設定は、Geminiの共通機能として転用していません。

提供状況にも注意が必要でした。[Gemini APIの廃止一覧](https://ai.google.dev/gemini-api/docs/deprecations#imagen-models)では、Imagen 4の対象モデルの終了日は8月17日です。これはGemini APIの記述であり、Vertex AIを含めたImagen全体の終了とは扱いません。再利用する指示にはモデル一覧や料金表を抱え込まず、作業結果に影響する機能だけ、その導入先で確認する形にしました。

動画は[Omni](https://ai.google.dev/gemini-api/docs/omni#gemini-omni-flash-prompt-guide)と[Veo](https://ai.google.dev/gemini-api/docs/veo#veo-prompt-guide)を個別に照合しました。特にOmniの延長は、新しい区間を起点に時刻を指定し、接続のため元動画の末尾フレームが変わる場合があります。プロンプトだけで元動画の完全な保持を約束しないようにしています。

## 全指示の再監査

同日、公式資料の更新反映に加え、Gemini関連3参照の全指示を、実際にこのスキルを使う側の判断手順として再監査しました。共通の`SKILL.md`との関係も読み、誰に向けた指示か、いつ適用するか、何を必須にするか、何を裁量に残すか、どこまで進めれば完了かを照合しています。対象モデルの仕様は前節の調査を引き継ぎ、新しい製品情報の追加は行っていません。

| 対象 | 確認と調整 |
| --- | --- |
| Gemini共通：対象・入力配置・根拠 | 対象製品と入力の役割を維持。未記載情報を不明として扱う原則に、依頼が明示した分類規則を適用する余地を残す。たとえば許可リストにない項目を対象外とする規則を妨げない |
| Gemini共通：説明量・例・推論・検証 | 共通本文と重なる一般原則を圧縮。例を使う条件と、改稿を試験するときの条件を分け、プロンプトを書くたびに追加試験を要求しない |
| Gems：継続指示・Knowledge・分割 | ルールの要点をInstructionsに置き、詳細をKnowledgeへ参照する分担を明確にする。重複禁止が必要な要点の保持まで禁じないよう調整。索引は優先順位だけでなく、参照先の選択や依存関係にも使えるようにする |
| Gems：情報源・共有・引用・保存 | 現行仕様と権限の境界を維持。長いKnowledgeの検証はGemを試験する場合に適用。報告は実施内容と重要な限界を伝え、全段階の定型的な振り返りを必須にしない |
| 画像：入力役割・構図・文字 | 指定された構図は保持し、構図を任された依頼では余白位置も選べるようにする。翻訳の確定文を指定することと、追加承認を求めることを混同させない |
| 画像：編集・反復・出力条件 | 照明・画風の変更と元画像の属性保持が衝突しないようにする。自然になじませる挿入物には元画像との整合を求める。寸法・透過・形式は出力要件として扱い、実行が範囲に含まれる場合は対応する設定や加工工程で満たす |
| 動画・音声・完了 | 時間、ショット、延長、音声の区別は維持。プロンプトだけのレビューと実出力の検査を分け、作成と生成を併せて依頼された場合は、既存の許可の範囲で生成工程へ進める |

3参照を通して14か所を変更しました。すべての文を言い換えることを目的にはせず、適用条件と意味が明確な指示は維持しています。特に「余白の左右を決めない」「編集の照明や質感を元画像へ合わせる」という従来の表現は、構図の設計や照明・画風の変更を任された依頼への適用が広すぎたため、条件を修正しました。

境界の確認には、許可リストによる分類、構図を任されたポスター、照明・画風を変える画像編集、翻訳文の作成、プロンプトのみの依頼、プロンプト作成と生成の併合依頼、InstructionsとKnowledgeへのルール配置を使いました。各依頼に対して指示文の適用条件を手作業で照合したもので、Geminiから回答や画像を得た動作試験ではありません。

## 残る懸案と検証記録

初回更新では`quick_validate.py`、`npm run check:plugins`、差分の空白検査が成功しました。JSON 14件、当時の指示10ファイルのハッシュ、manifest間の参照、ローカルリンク65件を照合しています。変更していない7ファイルの一致と、Gitの基点からGeminiの旧3参照を復元できることも確認しました。

再監査後もスキル・プラグインの検証が成功しました。JSON 15件、現行指示10ファイルのハッシュ、manifest間の参照、ローカルリンク68件を照合し、記録した差分から直前の3参照を復元できることを確認しています。保存後の3参照と本ノートを通読し、条件・例外の保持、重複、読み順を確認しました。
