このガイドは、dot用の共通指示の内容と設計意図を日本語で説明します。リポジトリでは `dot/AGENTS.md` として配布し、構築を依頼するときも `AGENTS.md` のまま渡します。ガイド自体は日常作業の指示を追加せず、毎回の読み込みも前提にしません。構築・更新の手順は `dot-setup.md` に分けます。

## 英語化の範囲

`AGENTS.md` は、取得元の英語表現と意味を照合しやすくするため、本文を英語で統一しています。英語の方が常に優れる、あるいは動作が実証的に最適化されたという意味ではありません。ファイルが英語であることは、ユーザーへの返答を英語にする指示でもありません。返答言語は、その場の依頼と適用される指示に従います。

特定モデル名や設定値は含めていません。指示の意味と適用範囲を明確にする設計であり、モデル間の性能差や実行時の効果を保証するものではありません。

## 取得元と採用範囲

土台となる公開ソースは、[peaceroad/ai-dotfiles の home/.codex/AGENTS.md](https://github.com/peaceroad/ai-dotfiles/blob/5af65a5d4f355f8063b0871ea5baac76d143d5fc/home/.codex/AGENTS.md) です。参照先を固定コミットにすることで、どの記述を元にしたかを確認できます。

直接の土台にしたのは `Response quality` と `Complete skill and reference loading` の二節です。前者は必要な説明・根拠・不確実性と重複の抑制、後者は必要な指示を欠けなく読むための具体的な手順を保っています。取得元の一人称の依頼表現は、共有文書に合わせて「ユーザー」に置き換えています。

結論や次の行動を先に示すこと、過度な称賛を避けることはdot用の追加方針です。参照範囲を今回の作業に限定すること、必要な資料を取得できない場合の扱い、保存と自動読み込み・実行許可を区別することも、dot用の補足として残しています。

取得元にある待機、外部ブラウザー、Windows のファイル参照、改行コードの各節は、このテンプレートには含めていません。dot向けに、適用範囲と承認、クラウド内配置、正本と更新の扱いを別に定めています。

上流の main が更新されても、テンプレートは自動追従しません。採用する記述の変更は、構築・更新の手順に従って判断します。

## 各部分の役割

### 冒頭の文書の分担

日常の共通指示、構築・更新の手順、導入する取得元・スキルを分けています。文書名は、今回渡された本文または同じ設定フォルダの文書を指し、特定の機器の絶対パスには固定していません。

`AGENTS-private.md` は任意の追加指示への入口です。渡されているか同じ設定フォルダに存在する場合に全文を読み、今回の作業に関係する条件だけを適用します。存在しない場合と、存在するが読めない場合を分け、後者ではその情報が必要な作業だけを保留します。非公開の参照先や個別条件を、公開本文へ移すための仕組みではありません。

### Scope and permissions

指示の優先順位と適用範囲を確認し、今回限りの条件を恒常的な方針に広げないための節です。操作の許可はアプリの有効な設定と承認手順に従います。このファイル自体は新しい権限を与えず、カスタムルールの写しも保持しません。

### Response quality

結論・結果・必要な次の行動を先に示しつつ、判断に必要な説明や注意点を残します。根拠から直接分かること、推測、未確認事項は、答えに影響する場合に区別します。

まとめや表を一律に禁じるのではなく、依頼または理解上の利点に応じて使い分けます。短さだけを優先して根拠や制約を削ることも意図していません。

### Complete skill and reference loading

作業開始時と、作業の種類や重要な条件が変わったときに、descriptionを基に適用するスキルを選びます。ユーザーが明示したスキルも対象です。ランタイムのカタログに説明があれば使い、管理スキルは構築時に確認した場所のINDEXから候補を探して、必要なSKILL.mdのdescriptionを確認します。INDEXがなければ、その場所のスキル入口のメタデータだけを調べます。

作業とスキルに変更がなければ、読み込んだdescriptionを再利用します。毎回全スキルの本文を読む指示ではありません。この選定手順はdot用の補足です。

選んだ `SKILL.md` と今回必要な参照資料は、依存する作業より先に全文読みます。関連資料を無制限に読み込む指示ではありません。

取得元に沿って、次の具体的な条件を明記しています。

- 指示ファイルごとに、上限内に収まる独立したツール結果で読む。他の大きな出力ともまとめない。メタデータはまとめてもよい

- 読み込みツールと外側の結果返却処理の両方の出力上限を考慮し、必要に応じてファイルサイズを確認して分割する

- 分割・省略があれば、先頭から末尾までの連続した範囲を確認し、不足を取得してから利用する

- 全文が省略なく一度に返った場合は、別途の範囲管理を求めない

保存しただけで自動読み込みやコード実行の許可が成立するわけではありません。必要な資料が取得できない場合は、その資料に依存する作業に限って保留します。

### Cloud workspace layout

dot 自身のクラウド内で、継続案件、取得資料、道具、スキル、残す完成物の置き場所を分けます。`shared` と割り当てられた作業ディレクトリの実際の場所・アクセス範囲は、その環境で確認します。

継続案件は `projects/` 内の本体で編集します。一時作業は割り当てられた作業ディレクトリ内に必要なときだけ作り、日付と短い作業名を使います。残すファイルを確認してから承認範囲で作業単位の片付けを行い、scratch 全体の定期一括削除は行いません。

### Canonical copy and updates

正本を一つに決め、必要なコピーを独立編集しないための節です。コピーからの自動書き戻しも前提にしません。保存場所と読み込み方法は構築時に確認します。

スキルの用途と読み込み先は `INDEX.md`、採用版と内容比較に必要な情報は `skills-manifest.json` に分けます。一般手順へ実測履歴や非公開の個別条件を埋め込まず、更新・差分・衝突の扱いは `dot-setup.md` に集約します。
