このガイドは、共通指示と選んだスキルをdot自身のクラウド環境に用意するために、何を準備し、どう依頼するかを説明します。初めて構築する場合と、以前に記録した版を再現する場合で、渡す資料と依頼文が変わります。

実行手順とmanifestの正式な仕様は英語の `dot-setup.md` にまとめています。JSONの記入例、各項目の意味、ハッシュの確認方法は、日本語の `skills-manifest-guide.md` を参照してください。どちらのガイドも利用者向けの説明であり、実行時の必須入力には含めません。

## まず用意する3つの文書

1. **AGENTS.md**：日常の作業で使う共通指示です。応答、資料の読み方、ファイルの配置、正本の扱いなどを定めます。

2. **dot-setup.md**：構築・更新・再現を行うための手順書です。既存内容の保護、スキルの取得と照合、管理ファイルの作成方法を定めます。

3. **dot-setup-private.md**：利用者自身が用意する選択一覧です。導入したいスキルの取得元、ブランチ、取得元内のパス、非公開ソースの利用範囲を記します。追加スキルが不要なら「追加なし」と書きます。

公開用の共通文書を使う場合も、選択一覧は自分の用途に合わせて作ります。他の利用者の非公開設定を入手する必要はありません。ファイル名の「private」は個別情報を共通文書から分けるためのもので、取得元がすべて非公開であるという意味ではありません。

文書はファイルとして添付するか、同名の本文だと分かる形で渡します。今回渡していない文書を、新しいdotが読めるとは限りません。必要な本文をその場で渡せるようにしておきます。

### 選択一覧の最小例

次の項目を埋めて `dot-setup-private.md` を作れます。取得元が複数ある場合は取得元ごとに分け、使うスキルを列挙します。不要な項目や未記入の例は残さず、分からない点は未確認だと明記します。

```text
# 導入するスキル

取得元：〈リポジトリのURL〉
公開区分：〈公開または非公開〉
ブランチ：〈使用するブランチ名〉
選択スキル：
- 〈スキル名〉：〈リポジトリ内のスキルフォルダのパス〉

非公開ソースの利用範囲：〈今回利用を認める対象と範囲。公開ソースのみなら「該当なし」〉
固定版の指定：〈特定版を選ぶ場合だけ、コミットなどを記入〉
```

認証情報、パスワード、アクセストークンは書きません。非公開ソースを指定してもアクセス権が新しく付くわけではなく、権限が足りなければ該当する作業が保留になります。

### 個別の追加指示がある場合

任意で `AGENTS-private.md` と、そこから参照する必要な文書を添えます。共通指示には含めたくない個別条件を、適用する場面とともに分けて書くためのものです。

追加指示を使わなければ、これらは不要です。使う場合は参照先の本文も渡します。配置や読み込みだけで、外部サービスの設定変更、監視、自動返信が始まることはありません。

## 初めて構築する場合

3つの文書を用意して、次の依頼文と一緒に渡します。個別の追加指示があれば、その文書も添えてください。

通常の新規構築では、指定ブランチの取得時点の最新HEADをリポジトリごとに一度だけ固定し、同じ取得元のスキルをそのコミットにそろえます。途中で上流に変更が入っても、確定した版で作業を続けます。特定のコミットなどを指定した場合は、その指定を優先します。 タグ、リリース、ソースアーカイブは、内容を固定したGitコミットと照合できるものだけが対象です。選択スキルの配置先の外に実行時の必須ファイルが必要な構成は、そのままでは扱わず、対象部分を保留して取得元や配置方法を確認します。

### コピーして使う依頼文

```text
添付のAGENTS.md、dot-setup.md、dot-setup-private.mdに従い、あなた自身のクラウド環境に共通指示と選択したスキルを新規構築してください。AGENTS-private.mdと参照文書も添付している場合は、それらも対象です。

配置と照合を行い、正本の保存場所と読み込み方法、INDEX.mdとskills-manifest.json、未完了・未確認事項を報告してください。
```

## 記録した版を同じ内容で再現する場合

以前と同じスキル内容が必要なら、3つの文書に加えて、再現したい構成の `skills-manifest.json` を渡します。個別の追加指示も再現する場合は、その時点で使っていた `AGENTS-private.md` と参照文書も必要です。

manifestには、採用した取得元と固定コミット、選択スキル、ファイルの内容を照合する情報が記録されています。この記録を指定することで、現在のブランチ先頭ではなく、そのとき採用した版を使います。

上流から変更したスキルがある場合は、manifestが参照する差分またはスキル一式の復元資料も添えます。ハッシュは内容が一致するか確かめるための値なので、ハッシュだけから編集内容を復元することはできません。元の共通指示を再現したい場合も、そのAGENTS.md本文を渡します。manifestだけで共通指示の本文まで復元できるとは扱いません。

### コピーして使う依頼文

```text
添付のAGENTS.md、dot-setup.md、dot-setup-private.md、skills-manifest.json、および必要な復元資料に従い、あなた自身のクラウド環境に共通指示を配置し、manifestに記録されたスキル内容を再現してください。今回は最新版への更新ではありません。AGENTS-private.mdと参照文書も添付している場合は、それらも対象です。

再現と照合を行い、正本の保存場所と読み込み方法、新環境のINDEX.mdとskills-manifest.json、未完了・未確認事項を報告してください。
```

固定版の再現が完了するには、必要な取得元・コミット・復元資料にアクセスでき、ファイル内容の照合が一致する必要があります。資料不足を最新版の取得で補っても、同じ内容を再現したことにはなりません。

## 完了時に確認すること

dotからの報告で、次を確認します。

- AGENTS.mdの正本がどこに保存され、どのように読み込まれるか

- 選択したスキルが配置され、必要な参照ファイルもそろっているか

- 採用ソースや記録内容との照合で、不足・余分なファイル・未解決の不一致がないか

- 日常利用の入口となる `INDEX.md` と、構成を記録する `skills-manifest.json` が保存されているか

- 未完了の工程と、その再開に必要な資料や承認は何か

INDEXにはスキルの用途と読み込み先、manifestには現在の採用版と内容照合の基準をまとめます。詳しい取得ログが必要な場合は別の取得記録に置き、manifestへ操作履歴や読了ログを重ねて記録しません。

ここで使うmanifestは、この手順で定めた独自の管理形式です。dotに組み込まれた標準仕様や、ファイルを置くだけで自動認識される機能を意味しません。JSONの項目、パスの扱い、ハッシュの計算と照合方法は、`dot-setup.md` の「Manifest format and verification」（manifestの形式と照合）だけを正式な定義として参照します。

## INDEX.mdの書き方

`skills/INDEX.md` は、どのスキルを何に使い、どの `SKILL.md` を読めばよいかを探すための一覧です。スキル名、短い用途説明、入口への相対リンク、`skills-manifest.json` へのリンクを載せます。正式な作成ルールは `dot-setup.md` の「Management files and completion checks」を参照します。

次のMarkdownは、架空の2つのスキルを載せた例です。実際に配置したスキルの名前・用途・パスに置き換え、`skills/INDEX.md` として保存します。

```markdown
# スキル一覧

作業に合うスキルを選び、対応するSKILL.mdと、作業に必要な参照資料を読んで使います。

## 用途と入口

- [example-review](example-review/SKILL.md)：文書の構成と説明の分かりやすさを確認する
- [example-check](example-check/SKILL.md)：文書内の参照先と記載内容の整合性を確認する

## 採用版と内容照合

取得元、固定コミット、ファイルの照合情報は [skills-manifest.json](skills-manifest.json) を参照します。
```

リンクは `INDEX.md` の保存先を基準にします。この例なら `skills/example-review/SKILL.md` と `skills/example-check/SKILL.md` が実在する必要があります。上のコードブロックは記入見本です。例のリンクは、実際のファイルをその配置で保存した後に使います。

スキルを追加・更新したら、配置済みのスキル、INDEXの一覧、manifestの `skills` が一致することを確認します。用途説明は、そのスキルの実際の機能に合わせます。固定コミット、ハッシュ、取得・検証履歴をINDEXに重複して書かず、用途やリンクに変更がなければ書き換える必要はありません。

既存スキルがなく、新たな追加もしない場合は、用途の一覧を「追加なし」にし、manifestへのリンクを残します。既存スキルがある場合は、今回の追加がなくても、その一覧を空にしません。

INDEXを保存するだけで、スキルの自動読み込み、カタログ登録、インストールが行われるわけではありません。実際の一覧には非公開のスキル名や用途が含まれ得るため、公開時は内容を確認します。

## 再現の範囲と資料の扱い

この手順が扱うのは、渡した指示文書と選択スキルのファイル配置・内容照合です。OSイメージ全体の復元、アカウント接続や権限、アプリのカスタムルール、ランタイムやパッケージの導入は含みません。スキルに付属するコードの実行や、監視・自動返信などの有効化も別途扱います。

保存したファイルが自動で読み込まれるか、スキルのコードが実際に動くか、外部リンクが使えるか、ファイルが永続的に残るかは、それぞれ別の確認が必要です。内容照合の成功だけでは保証されません。

共通文書とこのガイドを公開する場合は、個人情報、非公開の取得元、利用者固有の参照先を混ぜないようにします。`dot-setup-private.md`、個別の追加指示、manifest、復元資料は原則非公開で扱います。manifestにも非公開の取得元名や構成情報が含まれ得るため、確認せずに公開しないでください。

後で同じ構成を再現したい場合は、使った指示文書、manifest、必要な復元資料を一緒に保管します。更新した構成を採用したときは、更新後の照合済みmanifestも保管し、どの記録を再現したいのか分かるようにしておきます。

## 構成記録のファイル名と値

構成記録は `skills-manifest.json` です。スキルの採用版と内容を記録し、固定版を再現するために使います。lockファイルも一般に版や内容の固定に使われますが、この形式は特定のパッケージ管理ツールやスキルCLIのlockファイルとは互換ではありません。環境全体のバックアップも含みません。

取得元の固定版との関係は、`matches_upstream`（一致）、`intentionally_modified`（意図した変更あり）、`unverified_or_unresolved`（未確認または不一致が未解決）の英語の値で表します。一致の基準は記録したコミットであり、現在の最新版ではありません。

この手順で定義する形式は `schema_version: 3` です。異なる形式の記録を受け取った場合は、構造を推測して上書きせず、対象と対応方法を確認します。

## 公開リポジトリでの配置

ai-dotfilesでは、配布する実行用文書を `dot/`、日本語の説明を `docs/dot/` に置きます。これはリポジトリでの保管場所であり、採用後のdot環境の配置とは別です。

```text
ai-dotfiles/
├── dot/
│   ├── AGENTS.md
│   └── dot-setup.md
└── docs/
    └── dot/
        ├── agents-md-guide.md
        ├── dot-setup-guide.md
        └── skills-manifest-guide.md
```

`AGENTS.md` は配布時も採用後も同じ名前です。構築を依頼するときは、そのまま添付するか、同名の本文として渡します。`dot/AGENTS.md` はdot環境に採用するための文書です。リポジトリを編集するときは、ルートの `AGENTS.md` と各指示の適用範囲を確認し、配布文書の内容だけを根拠に環境構築を始めません。

リポジトリから取得するのは `dot/AGENTS.md` と `dot/dot-setup.md` です。3つ目の必須入力となる `dot-setup-private.md` は、利用者が自分の選択一覧として用意します。ガイド3つは任意の説明資料であり、構築のために必ず添付する必要はありません。

`home/` はホーム環境からのエクスポート先であり、dot用の配布文書は `dot/` と `docs/dot/` に分けます。

公開する5ファイルに、実際の選択一覧、個別指示、INDEX、manifest、取得記録、復元資料を混ぜません。公開用の例と実環境の記録を分けて保管します。
