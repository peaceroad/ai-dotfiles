# Marketplace management

Use for ai-dotfiles-managed distribution and consumer Skill copies. `agent dev marketplace` manages development; `agent marketplace` consumes published content. Connecting a Marketplace in the local index does not register it in Codex.

## Ownership and inspection

The shared `<root>/.agents/marketplace-development/config.json` generated by the orchestrator contains `managedBy: "ai-dotfiles/agent-dev"` and source-path-free assignments. Local sources and assignments live in the private development index. Neither generated package copies nor an installed cache becomes the editable source.

Use `agent dev marketplace status <target>` for metadata and plain `check <target>` for a read-only consistency report. Preserve scope and failed step when reporting unavailable shares; inability to read the NAS does not establish missing or matching contents. Review logs for private data before sharing.

`configure [<target>]` (alias `setup`) edits local configuration interactively. It does not assemble packages or register a Marketplace in Codex. A missing target is not authority to choose its ownership. The standalone assembler's `init`/`add` and an improvised external `--config` are not substitutes for this workflow.

## Synchronization scope

`agent dev marketplace sync <target>` assembles shared copies through the orchestrator:

- `authoritative`: unscoped sync uses the complete local assignment set.
- `contributor`: unscoped sync processes only local assignments as successive scoped operations, preserving unassigned entries.
- `consumer`: development check/sync is refused.

Use `--plugin <local-target>` or `--skill <local-target>` for one assigned package. Report selected-package success separately from full consistency. Contributor operations are not one transaction; a failure may leave earlier assignments updated.

If shared metadata changed since acceptance, full sync stops. `check <target> --interactive` offers importing shared assignments or explicitly switching to contributor. Accepting a choice changes local configuration and revision state; plain status/check never accepts a revision. Matching local/shared assignments can permit first full sync without a separate acceptance, recorded only after success.

Importing assignments does not fetch local source contents. Update or review those repositories before publishing them back. Modes do not switch automatically, and assignments do not identify or lock a plugin's individual developer. Two contributors working on the same plugin still coordinate source changes through their normal version control. Do not resolve conflicts by changing recorded digests or using an unrelated force flag.

Keep writes serialized through the orchestrator. Its lock, staging, copy verification, and overwrite refusal are command guarantees; do not reconstruct them manually. If a NAS operation fails, restore access within the authorized environment, establish whether the writer finished, inspect the affected scope, and then resume or check. Do not start another writer while one may still be active.

## Published content on consumer machines

`agent marketplace list [<target>]` or `agent marketplace skill list [<target>]` lists standalone Skills. `agent marketplace skill install|update <skill-name> [<target>]` and `remove <skill-name>` manage verified local copies. They protect unmanaged or locally changed destinations and do not update development sources or source links.

This Skill catalog is an ai-dotfiles/assembler convention, not a standard Agent Skills installer contract. Without a compatible CLI, do not emulate installation with an unchecked directory copy.

For plugins, use current Codex Marketplace registration and plugin installation commands against the assembled root; do not use developer plugin sync against generated copies. Use the client's existing registration/installation tools when available. Select by package, Marketplace, and source identity, not list position. Adding a local ai-dotfiles connection alone does not install any plugin for a consumer.
